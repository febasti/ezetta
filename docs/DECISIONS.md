# Decision log

Append only. Decisions in SPEC sections 2, 6, and 8 change only after a discussion, and the accepted change is logged here. Entries marked **needs confirmation** were provisional choices made during setup; the review of 2026-10-17 says where each stands.

## 2026-10-06: Project setup

**Toolchain versions.** Versions were chosen so that the pieces work together, not simply the newest of each:

- Electron 44.5.1, pinned exactly (SPEC 2, 6.3). Node 22.12 or newer is required to install and develop (`.nvmrc`, `engines`).
- Vite 7 and `@sveltejs/vite-plugin-svelte` 6, because electron-vite 5 supports Vite up to 7 and the newest Svelte plugin needs Vite 8. Revisit when electron-vite supports Vite 8.
- TypeScript 5.9, because typescript-eslint and svelte-check do not support TypeScript 7 yet.
- Vitest 5, Playwright 1.63, ESLint 10, dependency-cruiser 18, Zod 4 (runtime schemas for the IPC contract).

**Package manager: npm.** Fewest steps for contributors, no build-script approvals. Lockfile is committed.

**Main and preload build as CommonJS.** A sandboxed preload script cannot be an ES module, so `package.json` has no `"type": "module"`. All dependencies are `devDependencies` and get bundled by electron-vite (`externalizeDeps: false`), so the packaged app needs no `node_modules`.

**Layer imports (clarifies SPEC 6.1).** `shared` imports nothing from the other layers, and `core` does not import `shared`. The IPC contract therefore holds only schemas and types, and `main` maps core types onto them. Enforced in `.dependency-cruiser.cjs`, which was tested with deliberate violations.

**Content Security Policy.** The production policy is sent as a header by the `app://` protocol handler with a fresh nonce per load, so CodeMirror (which injects `<style>` elements) works without `unsafe-inline`. In development the renderer comes from the Vite dev server, which needs `style-src 'unsafe-inline'` and a websocket. **Needs confirmation:** this development-only relaxation, and the dev server as the renderer origin in development (SPEC 6.6 says the renderer loads from the app protocol, which is true for every built and packaged run).

**i18n: no library yet (provisional).** `src/renderer/i18n` is a small typed layer over `de.json` and `en.json` with `{placeholder}` support and a test that both files have the same keys and placeholders. SPEC 9 wants one library chosen in milestone 1. Plural forms and other ICU needs are the trigger to adopt one (for example a Paraglide or Fluent based one). **Needs confirmation.**

**Working name.** "WriteMirror" is a placeholder taken from the folder name. The app name is still **[OPEN]** (SPEC 2). `package.json` is `private` with license `UNLICENSED` until the license is decided.

**Not decided here.** The packaging tool is **[OPEN]** for milestone 1, so neither Electron Forge nor electron-builder is installed. No icon set and no bundled fonts yet. The tokens name Inter and Source Serif 4 and fall back to system fonts.

## 2026-10-06: Milestone 1, project and editor

**Focus on macOS first (maintainer's decision).** The Linux parts of the M0 spike (Wayland and X11, AppImage and deb, the Chromium sandbox in packaged Linux builds) and the widget and LanguageTool spike are postponed. Milestone 1 (editor and file handling) comes first. The code stays platform neutral, and the Linux checks move to when a Linux machine is available.

**New dependencies** (all permissive licenses, all bundled by electron-vite):

- `smol-toml` (BSD-3-Clause): reads and writes `project.toml`. Its writer is deterministic, which the manifest needs.
- `chokidar` 5 (MIT): recursive folder watching. SPEC 15 asks which library to use. Not yet tried on Windows and Linux.
- `@codemirror/state`, `view`, `commands`, `language` and `@lezer/highlight` (MIT): the editor (SPEC 2).

**Manifest.** Written by `serializeManifest`: fixed section order, sorted folder and item keys, default values omitted, unknown keys and tables kept (export profiles and so on). Order lists are inline arrays as in the SPEC example. Comments in `project.toml` are not kept when the app rewrites it. A manifest that cannot be read is never overwritten, and all structure changes are refused until it is fixed. A manifest with a newer `version` is refused.

**Reconciliation (clarifies SPEC 5.3).** Besides order entries without a file, settings keys and order lists that no order list mentions are also shown as missing, so renaming a file with a status or goal behind the app's back never orphans its settings silently. "Neu verknüpfen" moves position, settings, and everything below to an existing item. Reconciling alone never writes any file.

**Deleting.** Always to the system trash, checked on macOS. The manifest entry and the item's settings are removed with it.

**Names.** Groups and sheets may not be empty, longer than 120 characters, start or end with a dot or space, or contain `\ / : * ? " < > |` or control characters. Names clash case-insensitively, like macOS file systems. A sheet and a group with the same name in one folder also clash.

**Saving.** Autosave after 800 ms without typing, flush on blur, when switching sheets, and when quitting. Quitting flushes in `before-quit`, not in the window's close handler, because cancelling a close also cancels the quit (found by a test). When a file changes on disk while the editor has unsaved edits, the timer saves and the blur flush pause, a banner offers "Neu laden" or "Meine Version behalten", and only an explicit flush (switching sheets, quitting) writes the editor's text. Rationale: unsaved typing cannot be recovered, an external version usually can (git, sync history).

**Word counts.** `core/typst/text.ts` is a tolerant scanner for the v1 subset, replaced by the Lezer grammar in milestone 2. A citation or reference counts as one word until citations are rendered. Footnote text is counted separately. Function arguments (figure captions, table cells) are not counted. Headings count.

**Editor highlighting.** A simple line-based CodeMirror tokenizer for the v1 subset. Hides nothing. Replaced by the Lezer grammar in milestone 2.

**macOS menu.** SPEC 2 says no menu bar. Windows and Linux get none. On macOS a minimal application menu stays (App, Edit with Cut, Copy, Paste, Select All, Window), because those commands reach the page only through the menu. Undo and Redo are left out so CodeMirror's own history handles them. **Needs confirmation.**

**Shortcuts** (Cmd on macOS, Ctrl elsewhere): K command palette, P go to sheet, N new sheet, Shift+N new group, O open project, 1 and 2 toggle the sidebar columns. All live in `src/renderer/lib/commands.ts`.

**Icons.** One in-house set of small stroke icons (`src/renderer/ui/Icon.svelte`), to avoid a dependency for a dozen shapes. **Needs confirmation.**

**Projects.** A new project is created through the system save dialog, the folder name becomes the title, and the app opens the last project at launch. For tests and development, `WRITEMIRROR_PROJECT` names a project to open (ignored in packaged builds).

## 2026-10-06: Sheets column and project rename

**Parent groups show everything below them.** Selecting a group lists its own sheets and those of all subgroups as one list, depth first in manifest order (`flattenSheets` in `core/project/tree.ts`). This replaces the folder rows of SPEC 3.2, which is updated. A heading appears wherever the folder changes (path relative to the selected group, joined with "›"), and clicking it selects that group. Empty subgroups have no heading, so they show only in the Gruppen column. Dropping a sheet on another sheet's row moves it into that sheet's folder, before that row. Dropping on a group in the Gruppen column moves it there.

**The top row renames the project.** The top row of the Gruppen column is the project root. F2, its context menu, or "Projekt umbenennen …" in the project menu change `title` in `project.toml`. The project folder on disk is not renamed.

## 2026-10-06: Continuous view (read-only first)

**Approach chosen:** a read-only continuous view first, with editing across sheets as a possible later stage (listed in SPEC 12). Selecting a group, or several sheets with Cmd or Shift, shows them as one document in sheet order. A single sheet opens for editing as before. Clicking into the text opens that sheet with the cursor at the matching file offset.

**Relation to SPEC 6.4 ("one EditorView for the open sheet").** The continuous view is a second, read-only CodeMirror view over text read from the files. It is never saved, and only one view can ever write: the editor for the open sheet. Entering the continuous view first writes unsaved text and releases the editor, so the view reads current files and coming back to a sheet reads them fresh. Needs no change of the spec decision, but the maintainer should know it exists.

**Technical notes.** Sheet text is joined with a blank line and trailing line breaks are trimmed, so an offset in the view equals the offset in the file (`editor/flowDoc.ts`). The heading above each sheet is a block widget. Block widgets must use padding, not margins, because CodeMirror's height map ignores margins, which made clicks land on the next sheet (found by a test). The view reloads when files change behind the app and when the shown sheets change; the scroll position is kept.

## 2026-10-06: Editor display and tools (milestone 2, first part)

**Parser: hand-written, producing Lezer trees (deviates from the wording of SPEC 6.4).** `src/core/typst/parser.ts` is a small tolerant parser that returns a Lezer `Tree`, the same way `@lezer/markdown` does, instead of a generated LR grammar. Typst markup is context sensitive (`_` inside a word is literal, `*` pairs only when a closer exists, `#` expressions hold balanced brackets), which a hand-written parser handles more simply. The tree and the CodeMirror integration are what SPEC 6.4 wants: widget extents come from the parser and never from regular expressions. It never throws, keeps every node inside its parent, leaves anything it does not understand as plain text, and bounds its backtracking (found by a test: unmatched delimiters were quartic before). It is not incremental; it reparses a whole sheet, which is fast enough for single sheets. New dependency: `@lezer/common` (MIT). `@lezer/highlight` is no longer used directly.

**What is hidden and what stays visible.** Heading, emphasis, and strong markers stay visible, dimmed, and the text is styled. Highlight delimiters (`::`), link wrappers (`#link("…")[`), the `#quote(block: true)[` wrapper, and list markers (shown as bullets and numbers) are hidden, and comments become pills. A hidden range is shown again where the selection touches it, and "Quelltext" shows everything as written. Hidden ranges need no atomic ranges: the selection can only reach them by touching them first.

**Editing commands** live in `src/core/typst/edit.ts` as pure functions (text, tree, selection in; changes and new selection out), applied as one transaction each:

- Betont and Wichtig toggle `_…_` and `*…*`, wrap the word at the caret, and use `#emph[…]` or `#strong[…]` inside a word, where a delimiter would not work in Typst.
- Anmerkung toggles `::…::`.
- Kommentar highlights the selection (unless it already is) and puts `/*  */` right after it, so the comment belongs to it. With a caret it inserts an empty comment. An existing comment after the highlight is reused.
- Paragraph styles (heading 1 to 4, bullet, numbered, quote, body text) change the prefix of each selected line. Choosing the current style again returns to body text. A quote wraps the lines in `#quote(block: true)[…]`.
- Hyperlink writes `#link("…")[…]`. A bare domain gets `https://`, an e-mail address `mailto:`. Cmd-click on a link opens it in the system browser, for https and mailto only, checked in the main process.
- Typing the closing `==` of `==text==` turns it into a comment (SPEC 4.2), not inside code, math, raw text, or comments.

**Shortcuts** (Cmd on macOS): I Betont, B Wichtig, Shift+H Anmerkung, Shift+M Kommentar, Shift+K Hyperlink, Alt+0 to Alt+3 body text and headings, Shift+8 bullets, Shift+7 numbers, Alt+Q quote, Shift+U Quelltext. They are bound in the editor's own keymap (ahead of CodeMirror's defaults, where Cmd+I would select the parent syntax node) and listed in the command palette. Headings 4 has no shortcut.

**Toolbar (SPEC 3.3), first tranche.** Group "Prüfen" with Anmerkung and Kommentar, group "Ansicht" with Quelltext, and the command palette at the right. Einfügen (Beleg, Fußnote, Bild, Tabelle, Gleichung, Querverweis) follows with the elements that need margin notes and the bibliography. The selection popover (Betont, Wichtig, Hyperlink, Absatz ▾) and the paragraph style in the status bar follow SPEC 3.4. The slash menu is not built yet.

**Continuous view.** It uses the same markup display, and "Quelltext" applies to it too.

## 2026-10-06: Footnotes with notes in the margin, and a rounder-less UI

**Footnotes stay inline (after asking about a separate notes document).** A note is `#footnote[…]` in the sheet, at its marker, as SPEC section 2 says. A separate notes document was weighed (cleaner text, all notes in one place) and set aside: it would need a custom Typst function, rules to keep references and notes in sync when sheets move, and orphan handling, and the files would stop being plain compilable Typst. The "all notes in one place" wish is met by the notes panel instead, which lists and edits every note of the sheet without changing storage.

**Display.** In the margin (default), a note is a small superscript number in the text and a card level with it in a margin column; in the text, the number is followed by the note, dimmed; "Quelltext" shows the raw source. The mode is a display setting (toolbar menu "Fußnoten", palette). The text column narrows and moves left to make room for the cards (down to about 440 px). With less room than that the margin gives way to the notes panel on its own. The margin plugin keeps its layout while a scrollbar appears or disappears (hysteresis). The sheet header follows the moved text column.

**Editing.** A click on a marker, a card, or a panel entry opens a popover with a small editor on the note's inner text. Its changes are forwarded to the sheet as normal transactions at the matching range, so there is one undo history, and Cmd+Z and Cmd+Shift+Z inside the popover run on the sheet. The formatting shortcuts work inside it. Escape or a click elsewhere closes it. The "Fußnote" tool (Cmd+Alt+F) inserts an empty note after the selection and opens it; on an existing note it opens that note. Notes in comments, raw text, math, or code are not notes, and a note inside a note belongs to the outer one (all decided by the parser).

**Reveal rule for markers.** Only a caret strictly inside a marker's source reveals it (an arrow key into it, or a selection over it). A caret at either edge does not, so typing next to a note does not show `#footnote[…]`. This differs from the other hidden syntax (highlights, links), which reveals when touched, because notes are long.

**Numbering (SPEC 4.4).** Notes are numbered in project order: a sheet starts after the notes of all earlier sheets that are in the export. The restart rule is a project setting (`[footnotes] restart = "continuous" | "chapter"` in `project.toml`, in the project menu): with "chapter", numbers restart at each level-1 heading, and notes before a sheet's first heading carry on from the last chapter of the sheets before it. Sheet statistics carry the counts this needs (`footnotes`, `footnotesAfterChapter`). The continuous view numbers its combined text the same way. Word counts keep counting footnote text separately; the status bar says "Wörter in Fußnoten".

**Parser fix found on the way.** A bracket inside raw text or math (`` `code ]` ``) ended a content block early; the scanner now skips closed raw spans and math inside content blocks.

**Less rounded UI.** Radii are now 4, 6, and 8 px (were 6, 8, and 12). Only progress bars and drag handles stay fully round; the toolbar's search field is an ordinary rounded button. SPEC section 8 and `docs/DESIGN.md` are updated.

## 2026-10-07: Images

**Three forms, all plain Typst.** A figure is `#figure(image("assets/x.png", width: 80%), caption: [..]) <fig-x>`, a bare `#image(..)` is shown without caption or number, and an `image(..)` inside a paragraph is a small image in the text (height 1em by default). Only a literal relative path in a call is drawn as an image. Anything else (a computed path, several images in one figure) stays as source until subfigures arrive with the export work.

**Edits touch one argument.** `core/typst/args.ts` parses call arguments with their ranges. The properties popover (caption, alternative text, width or height) changes only the argument that was edited, so arguments the editor does not know are kept and undo works as for any text. An unbalanced caption is refused with a message.

**Where files go.** Images are copied into the project's `assets/` folder (SPEC 5.1) under a safe, unique name that keeps the original name's letters (`Mein Foto.png` becomes `Mein-Foto.png`), never over an existing file. The kind is taken from the first bytes, not the extension (png, jpeg, gif, webp, svg), and the limit is 30 MB. Insert by toolbar (file dialog), paste, or drop; up to ten files at once. Removing a figure removes the text only; the file stays, since other sheets may use it.

**Display and security.** The renderer draws images from `project-asset://project/<path>`, a protocol that serves only image files from inside the open project root. No file URLs and no new CSP sources besides `img-src` for that scheme.

**Numbering.** Figures are numbered in project order, like footnotes: a sheet starts after the figures of all earlier sheets in the export. The word before the number follows the project language ("Abbildung" or "Figure"). Chapter-based numbers (2.1) wait for the export profiles. Sheet statistics carry the count (`figures`).

**Popover placement.** The popover may open above the image when there is no room below; CodeMirror moves it as it grows.

## 2026-10-07: Widgets are atomic, never revealed by touch

**Footnote markers and images do not turn into their source when the caret comes near.** They are atomic ranges: arrow keys step over them, and Backspace or Delete next to one first selects it (the marker or image is drawn with an accent outline), and the next press deletes the whole thing. This replaces SPEC 4.3 rule 3 (reveal on touch) for these two widgets, and supersedes the "Reveal rule for markers" of 2026-10-06. Their source is only editable with "Quelltext" on. For a figure alone on its lines, the neighbouring line counts as adjacent, so Backspace on the empty line below selects it. In inline note mode (the note text stays editable) the opening and closing syntax are atomic and a press selects the whole note. Links, highlights, comments and list markers keep revealing on touch.

**Consequences.** The popover's "Quelltext zeigen" button for images is removed. A selected widget shows no text-formatting popover. Known gap: in inline note mode, a mouse selection that starts inside the note text and ends outside it can still cover only half of the note syntax.

## 2026-10-07: Formulas drawn by the Typst compiler

**Renderer: the Typst compiler itself.** A formula is drawn by the same compiler that makes the PDF, so the editor shows what the export will show, in the same math font. Other options were weighed: a WebAssembly Typst in the renderer (typst.ts) needs `wasm-unsafe-eval` in the CSP, which SPEC 6.6 forbids by omission, and adds about 28 MB; KaTeX or MathJax would need a Typst-to-LaTeX translation that never matches Typst's notation or output. The compiler runs as a child process from the main process (SPEC 6.1: `spawn`, no shell, fixed arguments, time and output limits, an empty working directory, Typst's own embedded fonts only), one call per formula, about 100 ms. No new npm dependency. This settles the preview half of the **[OPEN]** compile-process question only as far as formulas go: one-shot calls per formula, no long-running process yet.

**Where the compiler comes from.** In a packaged app it is the Typst binary in the app's resources (`typst/typst`, SPEC 6.3, packaging is still open). In development it is `WRITEMIRROR_TYPST`, then Homebrew or `/usr/local/bin`. Without a compiler a formula shows as its source, with a wavy underline. Formula end-to-end tests are skipped when no `typst` is installed.

**Code is not previewed.** A formula that contains `#` (Typst code: `#read`, `#import` of packages from the network, and so on) is never sent to the compiler. It shows as source with the message "Code in a formula is not previewed". The real export is unaffected.

**Drawing and baseline.** The page is `width: auto, height: auto`, text at 10 pt in a fixed ink colour that is swapped for `currentColor` afterwards, so one drawing fits both themes and the cache needs no colour in its key. An inline formula is preceded by a 1 pt marker box whose bottom edge is the baseline; the editor reads its position from the SVG, cuts the marker off, and aligns the drawing with the text. Sizes are in em, so the formula follows the text size. `core/typst/math.ts` holds all of this (page text, SVG reading, tests with a recorded SVG), `main/services/mathRenderer.ts` the process.

**Display.** Formulas are atomic widgets like images and footnote markers (see the entry on widgets above): arrow keys step over them, Backspace or Delete next to one selects it, a second press deletes it, and only "Quelltext" shows the source. A block formula (`$ … $`, with spaces) alone on its lines is a block widget, centred, with its `<label>` inside the widget's range and not shown; otherwise it is drawn in the line. Empty `$$` is an inline formula with a placeholder. A formula in a footnote, in function arguments, in code or in raw text stays source.

**Editing.** Click a formula (or insert one from the toolbar, `Alt+M`) and a popover opens with a text field for the Typst source, a switch between "Im Text" and "Abgesetzt", a preview that is drawn while typing (after a 120 ms pause, the drawing answers from a cache when it can), and "Formel entfernen". Each keystroke goes into the sheet as a normal transaction (undo works), so the formula in the text follows along. A formula that does not compile keeps its last good drawing, dimmed, and the compiler's first error shows in the popover. A new formula starts as `x` with the text selected; an empty block formula cannot exist in Typst, so a block starts as `$ x $`. A `$` typed in the field is written escaped (`\$`).

**Parser.** `$$` (an empty formula) is now a formula node. Numbering of equations stays with the template (SPEC 4.2); the editor shows no equation numbers.

## 2026-10-07: One quote feature, two forms

**One element, two forms.** A quote is Typst's `quote` element: inline (`#quote[…]`, part of a sentence) or block (`#quote(block: true)[…]`, a paragraph of its own). The toolbar's "Zitat ▾" menu has "Zitat im Text" and "Blockzitat", and each turns the other form into itself when the caret is in a quote: block to inline when the block is one paragraph, inline to block by splitting the paragraph before and after it (not in list items or headings). Shortcuts: `Cmd+Alt+Q` for the block (as before), `Cmd+Alt+G` for the inline form ("Gänsefüßchen"; `Cmd+Alt+Shift+Q` would be macOS's log-out shortcut). A selection of part of a quote's text becomes a quote inside it.

**The feature owns the marks, the file does not.** Typst's `quote` sets the quotation marks of the project language (checked: „…“ and ‚…‘ for German, “…” and ‘…’ for English; none for a block). So the file holds no marks, and the editor draws them as widgets replacing `#quote[` and `]`, with the inner pair at depth 1. Typed straight quotes (`"…"`) are left alone: Typst's smart quotes set them at export, but they are not a quote element, so the editor does not treat them as one. Languages other than German get the English marks until more are supported.

**Marks are atomic, but they are not widgets with content.** The caret cannot enter a mark, and the syntax never shows by touch. Backspace or Delete next to a mark takes the quote off and keeps its text (like deleting a quotation mark), without the select-first step that images, formulas, and footnotes have; undo brings it back. Arguments such as `attribution:` are kept and hidden with the opening mark; attributions wait for citations.

**Long quotes get a hint, never a rewrite.** While the caret is in an inline quote of at least 40 words (100 for Chicago styles; `blockQuoteWords` in `core/typst/quotes.ts` takes the citation style) a small button after the closing mark says "45 Wörter – als Blockzitat setzen" and converts on click. Nothing changes without the click, and short block quotes are never touched. The thresholds are defaults to confirm.

**Not yet.** A quote inside a footnote stays source in the note editor, as for images and formulas there. The read-only continuous view draws the marks but never the hint.

**Toolbar focus.** Running a command from the toolbar now puts the focus back into the editor first (a menu gives it back to its button), so typing goes on after choosing a menu entry.

## 2026-10-07: Block quote syntax stays hidden

The wrapper of a block quote (`#quote(block: true)[` and `]`) no longer shows when the caret touches it, as links still do. It is hidden and atomic like the marks of an inline quote, and Backspace or Delete next to it takes the quote off and keeps its text. Because hidden syntax at the edge of a line makes the caret just outside look like the caret just inside, a caret that lands outside (a click, Home, End, an arrow key from the line above or below) is moved inside, so typed text stays in the quote. The left arrow at the start of a quote's text and the right arrow at its end go straight to the neighbouring line. Only "Quelltext" shows the syntax.

**Quotation marks in block quotes: not added by the editor.** Typst sets no marks around a block quote by default (checked), and the editor shows none. Typst has `quotes: true` for it; where a project wants marks around block quotes, this belongs to the template and export profile (SPEC 7, the block quote group of the style schema), not to the sheets. Marks typed into a block quote by hand are ordinary text and work as they are.

## 2026-10-07: Quotation marks around block quotes are a project setting

This replaces the last paragraph of the entry above ("not added by the editor"). The maintainer usually sets block quotes in quotation marks, so there is a project setting, `[quotes] block_marks = true` in `project.toml` (default off), switched in the project menu ("Blockzitate mit Anführungszeichen"). It is a project setting, not a per-quote option, so all block quotes look the same and sheets stay free of styling.

**One source for the marks.** Marks never come from the text. Inline and block quotes alike get the marks of the project `language` (`quoteMarks` in `core/typst/quotes.ts`, the same table the editor uses for both): the editor draws them around the block, as for an inline quote, and the export emits `#set quote(quotes: true)` (in `assemble`, and in the template's prelude once milestone 3 builds it), so Typst sets the same marks from the same language. With the setting on, an inline quote inside a block quote nests and gets the inner pair (checked against Typst); with it off, it gets the outer pair. A block quote with several paragraphs gets one opening mark at its start and one closing mark at its end, as in Typst.

**Behaviour.** The marks are decoration only. The caret still cannot go outside them, typing at the edges stays inside, and Backspace or Delete next to one takes the quote off. Marks typed into a block quote by hand would appear twice, so with the setting on, do not type them.

## 2026-10-07: Citations: chips from the BibTeX data, no CSL engine

**Chips are a working view.** A chip need not look like the export (which may put citations in footnotes), only be readable. So the app formats chips itself from the BibTeX data (`core/bib/cite.ts`): author surnames and year, with the page reference after a comma; "und"/"and" and "o. J."/"n.d." by the text's language. This replaced the SPEC's citation-js/citeproc-js plan, which also avoids citeproc-js's CPAL-1.0 or AGPL-1.0 licence, so the licence of the app stays open. Typst still formats the PDF with CSL. Chips drawn with any CSL style (footnote and numeric styles included) are a possible later addition, and welcome.

**Reading the bibliography.** `library.bib` (the manifest's `bibliography` path) is read by a small hand-written BibTeX reader (`core/bib/bibtex.ts`: braces and quotes, `@string` macros, LaTeX accents and dashes to Unicode, names with particles and institutions, `and others`, damaged entries skipped and reported). A 8.5 MB parser package was the alternative; the reader needs only key, authors, year, title, and source. Cross-references between entries (`crossref`) are not followed. The session reads the file when the project opens and when the watcher reports it, and the snapshot carries a `bibliographyStamp`; the renderer reads the works again when the stamp changes, so Zotero's auto-export shows up at once.

**Syntax.** `@key` and `@key[S. 14]` (the short form) and `#cite(<key>, supplement: […], form: "prose" | "year" | "author")` (the long form). Keys that start with `fig-`, `tbl-`, `eq-`, or `sec-` are cross-references and stay text (SPEC 4.2). The editor writes the short form whenever it says everything and `#cite` otherwise, keeps `#cite` arguments it does not know, and never lets a short form join the text after it. Prefix and suffix (named in the SPEC) are not offered: Typst's `cite` has no such arguments.

**In the editor.** A citation is an atomic chip like images and formulas: never revealed by touch, Backspace or Delete selects it, a second press deletes it. A click opens a popover (work, page reference, form, remove). A key that is not in the library is a dashed red chip with the key, and while the caret is still at its end it stays plain text, so typing `@smi` is not interrupted. `@` opens a menu (key, author, year, or title words) via `@codemirror/autocomplete` (new dependency, the official CodeMirror package, MIT); the toolbar's Beleg and `Cmd+Alt+C` open a library dialog that inserts the work and puts the cursor in the page field. Chips also show in the continuous view and inside a note's popover editor.

**Not yet.** The Literatur sidebar and adding references (next steps); citations in the margin cards' text and the sheet previews still show the source; the word count does not treat a citation as its rendered text; the project warnings do not list unknown keys.

## 2026-10-07: Citation markers, the form `none`, and a bibliography file outside the project

**`form: none` and "Prosa".** The popover has a fifth form, "Nicht gedruckt" (`#cite(<key>, form: none)`: the work is listed in the bibliography, nothing is printed in the text; the chip is dashed). The `prose` form is labelled "Prosa" (English: "Prose"). The other Typst forms, `full` and a per-citation `style:`, are kept as written but have no button.

**A missing citation and a citation to check: both are comments (design choice).** The maintainer wanted markers that are never exported and that Typst does not know. A Typst block comment is exactly that, keeps the file valid Typst, needs no preprocessing, and shows up as a margin note when an export profile asks for comments (SPEC 4.5). The two forms: a block comment `cite-needed: note` (a place that needs a citation; a yellow chip "Beleg fehlt: note") and a block comment `check: note` right behind a citation with no space (the citation is to be checked later; a dot on its chip, the note as tooltip). The tags are language-neutral and the note is free text; the app writes a note on one line and without comment delimiters. There is no space in front of the comment, because a space would stay in the PDF. Both live in the Beleg dialog: the last row inserts a missing-citation marker (what was typed in the search field becomes its note, so "Studie zu Pendlern" with no matching work is one Enter away), and a check box marks the inserted work for checking. The popovers can also set or remove the check mark and note, and a missing-citation marker can be replaced by a chosen work. Both markers are atomic like the other widgets; the check comment belongs to its citation (removing the citation removes it). Only block comments count (a line comment would swallow the rest of the line).

**The bibliography file is read where it is.** Zotero and similar programs write the file, so it is not copied: the manifest's `bibliography` may be an absolute path, chosen with the system dialog (project menu, or "Datei wählen …" in the Beleg dialog); a file inside the project folder is stored relative to it. Reading outside the project is a deliberate exception to the rooted file system: `readExternalText` takes an absolute path, only `.bib` or `.bibtex`, a regular file (symbolic links are resolved first) of at most 50 MB, and nothing outside the project is ever written. The watcher also watches that one file and reports it by its absolute path. For the export, the compiler may only read inside the project, so `assemble` writes a copy into the generated `_build/` folder and points `#bibliography` at it. Consequences: `project.toml` holds a path that is only valid on this machine (a shared project needs each user to choose the file), and a hand-edited path is read only if it passes the same checks.

## 2026-10-07: Safer markers, a fixed row for a missing citation, and citing several works

**The markers start with `#` (replaces the syntax of the entry above).** A plain `/* check */` is easy to type by accident in an ordinary comment, so the markers are now `/*#check: note*/` (note optional, right behind a citation, no space) and `/*#cite-needed*/`. The `#` must follow the comment's opening at once; spaces inside the comment are tolerated, so `/*# check: x */` also works by hand. Comments written without the `#` are ordinary comments. Nothing was released with the old syntax, so there is no migration.

**A missing citation has no note.** The earlier flow (type words that match no work, and they become the note) was a trick; it is gone. The Beleg dialog has a fixed first row, "Beleg fehlt", that stays at the top while the list scrolls and whatever is typed in the search field; it inserts `/*#cite-needed*/` with one choice. A comment that says more than the tag is not a marker. Its popover has "Beleg wählen …" and "Markierung entfernen" only.

**Several works: citations next to each other.** Checked against the compiler: Typst prints citations that are only separated by white space as one group, in the style's order, "(Doe, 2018; Jones, 2019; Smith, 2020)", also with a comment between them; a semicolon in the text splits the group. So the file needs no new syntax: `@smith2020 @jones2019`. The editor makes it easy to write: the Beleg dialog has a tick box on every work (click it, or `Cmd+Enter` on the highlighted row; ticks stay while the search changes), a footer count and an "Einfügen" button, and Enter inserts the ticked works, or just the highlighted one when none is ticked. Clicking a row inserts it at once, unless works are ticked, then it ticks. A citation's popover has "Weiteres Werk …" (the same dialog, without the missing-citation row), which adds citations behind it. "Zur Prüfung markieren" marks every work of the group. Each chip keeps its own page reference and form. One known edge: a `none` citation inside a group leaves an empty place in the PDF ("(; Smith, 2020)"), so it should stand apart.

**Focus.** After a click on a row or a tick box in the dialog, focus returns to the search field, so Enter and typing keep working.

## 2026-10-07: A group of citations is one unit with one form

**Checked against the compiler.** Citations that are only separated by white space (a space, or one line break; also none at all, or a check comment) are one group, whatever syntax they use: `@a @b`, `#cite(<a>) #cite(<b>)`, or a mix. A group with different forms prints broken text ("Jones, 2019; Smith (2020)", "2019; Smith, 2020", `normal` + `none` gives "(; Smith, 2020)" or "(Jones, 2019)" depending on the sort order), so the `@` form is not required for groups, but the forms must agree. The members are also sorted by the style in the PDF, not in file order.

**What the editor does (unify automatically, not only warn).** `citationGroups` in `core/typst/citations.ts` finds the groups. The form belongs to the group: choosing a form in any member's popover sets it for every member (the popover says "gilt für alle n Werke der Gruppe"), and `none` therefore silences the whole group. Works added with "Weiteres Werk …" take the form of the citation they join. A citation typed, pasted, or inserted next to a group is made equal automatically: the group form is the special form the other members share (a newcomer is normally in the normal form, so the group's form wins wherever the newcomer stands); with two different special forms the first one in the text wins. Page reference, check mark, and work stay per member, and a short `@key` becomes `#cite(<key>, form: …)` when its form is not the normal one.

**When it happens.** Not while the key is still being typed: converting `@j` under the caret would get in the way. The conversion waits until the caret has left the group (or the editor lost the focus, which is also what opening a popover does), and it only looks at groups that were edited, so a mixed group elsewhere in the sheet, such as in a file written by hand, stays exactly as it is until the maintainer edits it. It is its own undo step and is not made after undo or redo (so Cmd+Z cannot loop; the first undo takes back the last typing, the next one the conversion). Notes' popover editors and the continuous view do not unify: they are not where the maintainer edits a group.

## 2026-10-07: A group of citations is one chip

The chip follows the PDF: citations that print together (see the entry above) are **one chip**, "Smith 2020; Jones und Müller 2019, S. 4", with "; " between the works and each work's own page reference. This shows at a glance that they are edited together. The chip is one atomic widget over the whole group (the white space between the members included): the caret cannot enter it, Backspace or Delete next to it selects all of it, and a second press removes all of it. A dot marks a group with a work to check; a dashed outline marks a group that prints nothing; a work that is not in the bibliography marks the chip as missing, with a tooltip for each such work. A citation whose key is still being typed (not in the library, caret at its end) is left out of the chip and stays text, so typing `@man` next to a group does not pull half a key into it.

**The popover edits the group.** One row per work: the work, its page reference, the mark to check it later (with a note), and remove (the white space that joined it to its neighbour goes with it; for a single citation it says "Beleg entfernen", in a group "Werk entfernen"). For the whole group: the form (five buttons, "gilt für alle n Werke der Gruppe") and "Weiteres Werk …". Opening the popover from an insertion puts the focus in the page field of the work just inserted. Removing a row keeps the focus in the popover.

## 2026-10-08: One citation editor instead of a dialog and a popover

The Beleg dialog (choose) and the citation popover (edit) were two modes for one job, and they needed bridges: "Weiteres Werk …", a separate dialog to replace a marker, tick boxes for several works, and no way to change a work later. They are now one editor, anchored at the caret for a new citation and at the chip for an existing one (also for a missing-citation marker). The modal dialog and its state (`ui.citePicker`) are gone.

**One field.** The works of the group are chips in a field with the search after them. Typing searches the bibliography (the works already in the group are left out; a fixed first row, "Beleg fehlt", is offered only while nothing is inserted yet); Enter or a click adds the work as a chip. The first work inserts the citation into the text at once (one transaction with opening the editor on it, so it never closes in between), and the editor stays open for more. Closing it with nothing chosen inserts nothing. Backspace in the empty search selects the last chip, and a second press removes it; the arrow keys move between the chips; removing the last work removes the citation and leaves the editor open for a new one at its place. Escape closes the editor (or first leaves a selection the maintainer made).

**Changing a work later (the point of the idea).** Clicking a chip (or moving to it with the arrow keys) selects it for replacing: the search placeholder says so, and the next work chosen replaces that work, keeping its page reference, check mark and form. A work selected only so that its row shows after an insertion does not replace anything: the next choice adds a work.

**Per-work details: a row under the field.** The selected work's page reference, "Zu prüfen" mark with note, and remove button are in a row below the results, so the field stays clean with many works. With no chip selected the row shows a hint. The form (five buttons) is below it, for the whole group. The footer names the bibliography file and changes it.

**Unchanged.** The `@` menu in the text, the groups as one chip, the forms, the check mark and missing-citation syntax, and the automatic unifying of a group's form.

## 2026-10-08: Superscript, subscript, and small caps

Added to the element set (SPEC 4.1 and 4.2) as the Typst functions `#super[…]`, `#sub[…]`, and `#smallcaps[…]`; Typst has no shorter markup for them. ## 2026-10-08: Tables, drawn and edited in place

**Edited in place, tried first in a spike.** The maintainer preferred editing the cells in the table itself but worried it would lead to complications, so it was built as a spike with the hard cases tested before anything else: typing while the table is redrawn under the field, undo and redo, Tab and the arrow keys, structure changes while a cell is being edited, paste from a spreadsheet, a table that grows, and many repeats for stability. It held, so there is no popover grid. This makes the table the one widget with editable content (an exception to SPEC 4.3 rule 2, noted there). It works because every change is still a normal transaction on the sheet: typing in a cell changes only the text between that cell's brackets (`cellEdit`), and the redraw (`updateDOM`) patches the cells that changed and leaves the field that has the focus alone, except to follow undo. Structural changes rewrite the table once (`rewriteTable`), and the editing goes on in the same cell.

**What is a table.** `#figure(table(…), caption: […]) <tbl-x>` and a bare `#table(…)`. Read: the number of columns or a list of widths, an alignment (a list of left, center, right, or one for all), a header row (`table.header[…][…]` or with parentheses), and cells that are content blocks; the last row may be short. Arguments the editor has no field for (stroke, inset, a figure's placement, …) are kept as written, and an `align:` it cannot read (a function) is kept too. A table with merged cells, lines, a footer, code or a spread in place of a cell, content blocks after the call, or a header of the wrong width is **not** drawn and never rewritten: it stays source. A table that is not alone on its lines stays source, because a block widget needs the lines. Tables in footnotes are not drawn.

**Look and numbering.** Hairlines above and below, a stronger line under the header row, the writer's alignment per column, "Tabelle N:" and an editable caption under it, in the project language's word. A table in a figure is numbered across the project like figures (`tables` in the sheet statistics, `tableOffset`); a bare table has no number. Cells draw emphasis, strong and citations; everything else (formulas, links, code) is shown as written, so nothing is hidden that cannot be edited there.

**Editing.** A click puts the cell into a text field with its source; Tab and Shift+Tab move on (Tab out of the last cell leaves the table), Enter moves down (in the last row it adds a row, so a table can be typed in without the mouse), the arrow keys move at the edges of the text, Shift+Enter is a line break in the cell, Escape leaves. Brackets that do not match are not written (the cell says so until they do). Several cells copied from a spreadsheet (tabs and lines) paste into the table from the cell, which grows if it must. A toolbar above the table while a cell is edited: row above and below, delete row, column left and right, delete column, alignment of the column, the header row, "Beschriftung hinzufügen" for a bare table, remove the table. The caption is a field under the table; emptying it takes the caption out. Each toolbar action is one undo step.

**Creating.** "Tabelle" in the toolbar opens a size picker (hover shows rows × columns, click inserts, arrow keys and Enter work too); the table has a header row of empty cells and a label `tbl-tabelle` (numbered if taken), and its first cell is ready to type in. `Insert table` in the command palette makes 3 × 3. The label is made once and is for cross-references.

**Side effect.** The toolbar was one step too wide for 1280 px with the new button; the tool buttons are 4 px narrower.

**Not yet.** Merged cells, lines, and column widths in the grid (they stay in the source and survive edits only as arguments the editor keeps); a table inside a footnote; icons on the table toolbar (words for now).

**Headings can be referred to.** Do cross-references to headings make sense? They do: Typst refers to a heading with `@label` like to a figure, and a thesis refers to sections all the time. ## 2026-10-08: Spelling and grammar with LanguageTool

**Only the open sheet is checked.** The whole project never needs checking, so there is no project-wide or group scope: the Prüfung tab and the status bar speak about the open sheet, and the "background check of the project" from SPEC 12 is dropped from the plan.

**Engine.** LanguageTool 6.6, the standalone package, run as a local child process (`java -cp languagetool-server.jar … HTTPServer --port N`, `spawn` without a shell, localhost only, 768 MB heap, a free port picked per start). `main/services/languageTool.ts` supervises it: it starts on the first check (or when the renderer asks), polls `/v2/languages` until it answers, restarts it up to three times after it died (at the next check), and stops it on quit. Its state (`off`, `starting`, `ready`, `missing` for no package or no Java, `failed`) is pushed to the renderer and shown in the status bar. The app works normally meanwhile. Nothing leaves the machine. In development the package lives in `.dev/languagetool/` (ignored by git; `WRITEMIRROR_LANGUAGETOOL` and `WRITEMIRROR_JAVA` name other places, and `WRITEMIRROR_LANGUAGETOOL_PORT` uses a server that already runs at that port of 127.0.0.1 instead of starting one, which the proofing tests do to share one server for the file); packaging with a trimmed Java runtime stays postponed with the rest of packaging. The maintainer-provided server URL of SPEC 4.7 and the optional n-gram data are not built yet.

**What the checker reads (`core/proof/extract.ts`, pure, tested).** The sheet is cut into units: a paragraph, a heading, a list item, or the text of one footnote, and each unit is sent as LanguageTool's annotation: runs of text and runs of markup. The runs cover the unit's source exactly, so the checker's offsets are source offsets and no mapping is needed. Markup stands for words with `interpretAs` where grammar needs it: a group of citations for its chip text ("Smith 2020; Jones 2019"), a cross-reference for what the PDF prints ("Abbildung 3"), an inline formula for `x`, a link for "Link", inline code for "Code", an escaped character for itself. Footnote markers, comments, labels, display formulas, code, raw blocks and the arguments of figures and tables stand for nothing (captions and table cells are not checked yet). The text of a footnote is its own unit, so it never mixes into the sentence it hangs on; blank lines, headings and list items end a unit; a unit that is only markup is not sent.

**Results.** A match becomes an issue with its category (spelling, grammar, style, typography, from the checker's issue type). A match that lies wholly inside a stand-in is dropped (it is about the stand-in). Suggestions are left out when the issue touches markup (applying one would replace a citation) and when they contain characters that would start Typst markup. Words of the two dictionaries are dropped after the check, so a new word takes effect without asking again. Results are cached per unit (language, level, disabled rules and the unit's runs), so typing re-checks only the changed paragraphs, a moment (0.9 s) after typing stops.

**Dictionaries and settings.** A personal dictionary lives with the app's settings (`settings.json`), a project dictionary in the project's `dictionary.txt` (one word per line, `#` comments, versioned with the project). Per project, in `project.toml` under `[proofing]`: `language` (the variant, for example `de-AT`; the project language decides when it is missing: German is `de-DE`, English `en-GB`), `level` (`default` or `picky`), `disabled_rules`, and the new `disabled_categories` (the four kinds, filtered after the check, so turning one off needs no new check). Switching proofing off altogether is an app preference. "Ignorieren" is for the session only (rule, words and the line around them).

**The editor.** Built on `@codemirror/lint` (new dependency: the official diagnostics, hover tooltip and actions, instead of writing them again). The underline is a text decoration in the colour of the kind (the extension's own is an image, which the CSP would not like). The tooltip shows the explanation and up to five suggestions as buttons, and "Zum Projektwörterbuch", "Zum eigenen Wörterbuch" (spelling only), "Ignorieren", "Regel ausschalten". ## 2026-10-08: Synonyms, in the form the sentence needs

**The question was inflection.** A thesaurus knows base forms, and replacing "Ergebnisse" with "Resultat" is bad: the plan was a lemmatizer, so that synonyms come in the right form, with a palette as the fallback if that were too much work. It was not: LanguageTool, which the app already ships for proofing, has German and English taggers (word → base form and grammatical tag) and synthesizers (base form and tag → form). Its HTTP API does not expose them, so a small Java helper uses the classes directly. No palette was needed; the context menu offers the forms ready to use.

**Flow.** A right click on a word (`wordInContext`): the paragraph is read as plain text (the same text the checker reads, with citations, references and formulas standing for words), so the sentence is right for disambiguation. `analyze` returns the readings of the word (base form and tag, for example `Ergebnis` and `SUB:NOM:PLU:NEU`). The readings are grouped by base form and kind of word; a German word with a capital in the middle of a sentence is a noun and one without is not (at the start of a sentence both are tried); the verb comes before the noun before the adjective for a lower case word. The thesaurus entry of each base form is read (as written, lower case, capitalised), the senses of the right kind kept (WordNet labels them; OpenThesaurus does not), and `inflect` gives each synonym's forms for each reading's tag. Where a word has several readings (case and number are often ambiguous: "Fortschritte"), the form most readings agree on is taken, and a subjunctive counts half as much as an indicative. A participle is inflected as an adjective. A German noun is kept to its own gender if the synonym has a form in it; otherwise the form of the other gender is offered with its article ("der"), but not in the plural, which has one article. A lower case "noun" form is a verb used as one ("das Erklären") and is dropped. A phrase cannot be inflected, so it is offered only for a word in its base form. Broader, narrower, related and opposite terms are left out; usage notes ("ugs.") are shown.

**Parts.** `core/thesaurus/entry.ts` (entry and note parsing), `core/thesaurus/lookup.ts` (the flow above, pure, with ports for the analysis and the thesaurus, tested with fakes), `main/services/thesaurus.ts` (the MyThes files, read once and indexed by byte offsets: 50 MB, a second at most), `main/services/morph.ts` (the helper process: started at the first question, one JSON line each way, 30 s timeout, killed on quit; in development `tools/morph/Morph.java` is compiled to `.dev/morph` when its class is missing or older, with the `javac` that sits next to `java`), `shared/thesaurus.ts` and the `thesaurus.synonyms` call, `features/editor/synonyms.ts` and the context menu. The first right click after launch starts the helper (a second or two for the dictionaries), so that menu may say "Synonyme werden geladen …"; the next has them. Without a helper (no Java or no LanguageTool) words in their base form still get synonyms. A real-helper test and an end-to-end test run when `.dev/` has the files.

**Data.** `npm run fetch:dev-data` downloads LanguageTool and the thesaurus files into `.dev/` (not in git): OpenThesaurus' German thesaurus (snapshot of 2017, as LibreOffice ships it, LGPL 2.1 or later) and the WordNet-based English one, 50 MB together. A newer OpenThesaurus export exists in another format and could replace the snapshot later. Both licences go with the files when the app is packaged (SPEC 15).

**Not yet.** A lookup field for any word, other languages than German and English, the thesaurus in the continuous view, and packaging of the helper's class and the data.

## 2026-10-08: The export, first slice

**Scope.** The maintainer chose: ask where to save each time, and no preference for the base template (more templates come later anyway). The first slice is the whole path from sheets to a PDF with one template, so that the rest can be added to something that works: preprocessing, assembly, the compiler, the dialog, the diagnostics. The old "assemble dry run" (command, menu item, IPC call, `core/typst/assemble.ts`) is gone; `core/export/build.ts` replaces it.

**Heading references without the template.** A reference to a heading is rewritten during preprocessing to `#link(<sec-x>)[Abschnitt 2.1]`, with the number the app counts across the export (the same `numberTargets` as the editor's chips, so editor and PDF agree). Typst needs only the label (the hidden `<sec-…>` the app writes), not heading numbering, so a template cannot make it fail. The template declares in `template.toml` what its engine does (`heading_numbering = "decimal"`): the engine numbers headings 1, 1.1, 1.1.1, and the app uses the same fact for its link text; for `"none"` the link shows the heading's title in quotation marks. References to figures, tables and equations stay native (`@fig-a`): Typst's counters are always right, including chapter-based numbers, and need nothing from the app. A reference to a heading that is not in the export is reported before the compile (and the compiler's own error is mapped too).

**Files.** `_build/main.typ` (generated: imports the prelude and the template, `#show: project.with((title, lang, …options))`, `#set quote(quotes: true)` if the project wants it, the sheets with a paragraph break between, and `#bibliography("/library.bib", title, style)` only where something is cited), `_build/content/<sheet>` (preprocessed copies), `_build/template/` (a copy of the chosen template's `lib.typ` and `style.toml`, because the compiler may only read inside the project), `_build/prelude.typ`, and `_build/out.pdf`, from which the PDF is copied atomically to the place the maintainer chose. A bibliography outside the project is copied to `_build/bibliography.bib`. `--root` is the project, `--ignore-system-fonts` is on, so the output is the same everywhere; the template uses Typst's embedded Libertinus Serif, New Computer Modern, and DejaVu Sans Mono (no fonts to ship yet).

**Preprocessing (`core/export/preprocess.ts`).** Changes only these things, each keeping the number of line breaks, so a compiler message at line n of the copy is line n of the sheet: highlights `::x::` (marks removed, or `#highlight[x]`), comments (Typst comments print nothing; for a review `#footnote[…]` with the text escaped so nothing in it is markup, and not inside a footnote, which cannot hold one), references to headings, and image paths (made absolute from the project). The app's own markers (`/*#cite-needed*/`, `/*#check: …*/`) stay comments and are only counted. Each rule is a list of edits that are applied together, so one that overlaps another is dropped, not mangled.

**Template contract as built.** A template is a folder with `template.toml` (id, names, description, `engine`, `heading_numbering`, and the options: text, bool, enum, with labels in German and English), `lib.typ` (the engine: `project(meta, body)`, no visual values) and `style.toml` (all values: margins, fonts, heading sizes and spaces, quote, figure, table rules, footnote, title page). The dialog's options form is generated from `template.toml`; the profile's values are checked against it (an unknown option or value falls back to the default) before they reach Typst as a dictionary of strings and booleans, quoted so a value cannot break out. "Abschlussarbeit": title page, contents (roman page numbers), optional lists of figures and tables, chapters on new pages, arabic page numbers from the first chapter, numbered equations, footnotes at the bottom, booktabs-like tables. Bundled templates are read from `templates/` in the checkout (packaging will ship them as resources); templates inside the project are not read yet.

**Profile.** `[[export]]` in `project.toml`: name, template, `citation_style`, `marks`, `comments`, and `[export.options]`. The dialog edits the first profile and saves it when an export starts; one profile ("Abgabe") for now, a list with names comes with the second template. Citation styles map the app's ids to Typst's bundled CSL styles (`core/export/styles.ts`: APA 7, Chicago author-date and notes, Harvard, MLA, IEEE, Vancouver, Nature); a custom CSL file is not offered yet.

**Warnings and errors.** Before the export the dialog lists what is open: comments, missing citations, citations marked to check, citations without an entry in the bibliography (the compiler would stop at the first and say it in English), and references to headings that are not in the export; each is a link to its sheet. After a failed export each compiler error is listed with its sheet and line (a click opens the sheet there); errors in the template or main file say "Vorlage". The compiler runs with a 3 minute limit; without Typst installed the dialog says so and the button is off.

**Not yet.** The paged preview, margin notes for comments, the Artikel and Prüfversion templates, templates inside the project, a custom CSL file, several named profiles, Word and Markdown export, golden tests per template, and shipping Typst and the templates when packaging.

## 2026-10-11: Quotes can be seen, and quotation marks typed by hand become quotes

## 2026-10-11: Three kinds of quotation, with the source in `attribution`

**The problem.** A block quote's citation was typed inside the quote (`#quote(block: true)[Text @key]`), so it was part of the quoted text: in the PDF it sat inside the quotation marks, and the editor could not tell it from the quote. **The model.** Three kinds, one `quote` element (SPEC 4.1): in the text, a block quote, and an epigraph. The source of a block quote is the quote's `attribution`, written as markup in brackets, so a citation there is an ordinary citation (`@key[S. 12]`) that groups, counts in the Literatur sidebar, and prints "(Kant, 1781, S. 12)". **The epigraph is a label, not a function.** An app function (`#epigraph`) was the other option. The label `<epigraph>` after a block quote is plain Typst (a sheet still compiles outside the app, and without the template it is simply a block quote), it needs no prelude in the generated main file, and a show rule can select it. Its source is free text, as asked (`attribution: [Goethe, _Faust_]`), edited in a field under the motto; markup such as `_Faust_` is typed as is. Citing a work from the library as the source of an epigraph is not offered.

**Conversions.** Block to text: the attribution's citations move behind the quote (a free-text source blocks the conversion, to lose nothing). Text to block: the citation right after the quote moves into the attribution. The Zitat menu lists the three kinds, and the paragraph style "Epigraph" toggles the label.

**The template.** The bundled template's block-quote rule printed only the body, dropping the marks and the attribution. ## 2026-10-12: Versions of the project, on by default, in a hidden folder (changes SPEC 6.5, rule 5)

**What changes in SPEC 6.5.** Rule 5 said to offer to initialize git in the project folder. The maintainer chose instead: versions are on by default, kept in a hidden folder, and handled through a dialog from the project menu (SPEC 3.9). Nothing is offered or set up. The rule now says that, and that a backup is recommended separately.

**Git underneath, without git.** `isomorphic-git` (new dependency, pure JavaScript, about 5 MB unpacked, bundled into the main process like `chokidar`) keeps the versions in `.writemirror/history.git`, with the project folder as its work tree: no git on the machine is needed, the project's own `.git` (if any) is not touched, nothing shows in the project folder, and copying the folder copies the history. Hidden files and folders are not scanned or watched, so the store does not stir the watcher.

**No index.** A version is made by reading the project's files, hashing them, writing the blobs that changed and the trees directly, and committing that tree. git's own index compares files by size and by the second of their modification time, and misses a change that keeps its size within the same second (found with a test that edits "Alt" to "Neu"); an edit lost from the versions is worse than reading a few small files every ten minutes. Files over 25 MB are left out.

**When.** Soon after the project opens (2 s), then every 10 minutes while something changed (checked by content, so an idle project takes none), when the project closes, and before an export (its own kind, shown as "Vor dem PDF-Export"). Named versions are kept even when nothing changed since the last one, because the name is the point. All of this runs in the main process and is queued, so two never work on the store at once, and a failure is logged and never reaches the writer's text.

**Restore.** The dialog lists the sheets that differ from now in the chosen version (changed since, or deleted since), not what the version changed compared with its predecessor: that is what a restore can act on, and a named version with no change of its own would otherwise list nothing. Sheets that are new since are not listed, since a restore removes nothing. A restore saves the present state first (kind `restore`, only when it differs from the last version, so it can be undone), then writes the file through the same atomic write as every file; the watcher reports it as a change from outside, so the open editor reloads it. Unsaved text is written before the dialog opens and before a restore. The comparison is a word-level diff (`core/history/diff.ts`), with a fall-back to one replaced block for huge changes.

**Not done yet.** (Done later: see the entry on restoring everything.) Restoring other files than sheets (the manifest, the bibliography, images), restoring a whole version at once, and the second half: a backup to a folder (zip copies, thinned out), with its setup card and status indicator.

## 2026-10-12: Backup to a folder (second half of the versions feature)

**Why a second thing.** Versions live in the project folder, so they protect against the writer's own mistakes but not against losing the disk. A backup copies the project somewhere else. It is in the same dialog (the tab "Sicherung"), set up in one step: choose a folder.

**A folder, not an account.** The writer chooses a folder, best one that a cloud service syncs (Dropbox, iCloud Drive, OneDrive, Nextcloud) or an external drive. That gives an off-site copy with no login, token or server in the app. A remote git service was left out: it needs credentials, which is not for non-technical writers. The folder is stored in the app's settings per project folder (`settings.json` in the user data folder), not in `project.toml`, which travels with the project to other machines where a path to a drive means nothing. The folder must not be inside the project (the zip would contain its own zips); it is checked to exist and to be writable before it is accepted.

**Zip files.** Plain zip archives (named `Titel 2026-10-12 14.30.zip`) that any computer opens, so a backup can be restored without the app: unzip it. Written by a small streaming writer (`src/main/services/zip.ts`, no new dependency): each file is compressed as a stream with its size and CRC after it (a data descriptor), so a large image is never held in memory; names are UTF-8; it refuses archives over 4 GB or 65,535 files rather than write a broken one, and is checked in tests against `unzip -t` where that exists. The archive is made under a hidden temporary name in the backup folder and renamed when complete, so a drive pulled out in the middle leaves no broken backup. The version history (`.writemirror`) is inside the zip, so a restored folder has its versions too; `_build/` and `node_modules` are left out, and symbolic links are not followed.

**When.** After choosing the folder (at once), then a check every five minutes: a backup is made if the project changed since the last one (a fingerprint of the files' names, sizes and modification times, so it needs no reading of contents and no version) and the last backup is an hour old; when the project closes if it changed, limited to 8 seconds by an abort signal so a big project cannot hold the quit up; and on "Jetzt sichern". A failure never reaches the text: it is the status's error, shown in the dialog and the status bar. A folder that is not there (an unplugged drive) is reported as "nicht erreichbar", not as a failure of the app.

**Thinning.** The newest 10 are kept, and beyond them the newest of each day for two weeks, of each week for twelve weeks, and of each month for two years (`backupsToDelete` in `core/history/backup.ts`, pure and tested). Only files that follow this project's title and the naming pattern are considered, so nothing else in the folder is ever touched, and they go to the system trash (SPEC 6.5, rule 3), not to deletion. The time is read from the name, which a sync service does not change, unlike a modification time.

**The nudge.** No card or dialog appears by itself. The status bar says "Nicht gesichert" in the warning colour until a folder is set, and it opens the tab: always visible, never in the way.

## 2026-10-12: Restoring any file, the whole project, and a backup

**Any file, as bytes.** The list of a version now has every file that is not the same now, not only sheets: the manifest, the bibliography, the dictionary and images too. A restore writes the bytes of the version (`readBytes`, `writeBytesAtomic`), not a decoded string, so an image comes back unchanged. Text files are compared word by word as before; a file with a NUL byte near its start, or over 2 MB, is "not text" (`isBinary`) and is shown by its size, with its restore button. Restoring `project.toml` goes through the same watcher refresh as any change of the manifest from outside.

**Everything at once.** "Alle … Dateien zurückholen …" asks first (it is a big step even though the state before is saved as a version) and then restores every listed file. It removes nothing by itself. A checkbox, off by default, adds the files that did not exist in the version (listed as `newSince`) to the same restore, and they go to the system trash (SPEC 6.5, rule 3), never deleted, so even that can be undone from the trash. Everything is one `restore` version beforehand.

**A backup is opened, never laid over the project.** "Als Projekt öffnen …" unpacks a backup into a new folder that the writer chooses and opens it. It never overwrites the project that is open: laying a zip over a living project would mean deciding file by file, and the versions (restore a sheet, or everything) already do that job with the writer's own history. The new folder has the project's old name, or a number when that is taken. It is unpacked into a hidden temporary folder inside the chosen one and moved into place when complete, and the check that it holds a `project.toml` comes before the move, so a wrong zip leaves nothing behind. The welcome screen has the same for a backup file picked from anywhere: the way back on a new computer, with nothing set up. (A restored project starts without a backup folder of its own: the setting belongs to the project folder on that machine.)

**A zip reader that does not trust the zip.** `src/main/services/unzip.ts` (no new dependency) reads the central directory and unpacks stored and deflated files. Every name is checked first (`safeEntryPath`: no absolute path, drive, `..`, `.`, backslash or NUL), and the resolved target must lie inside the folder, so a hostile archive cannot write elsewhere (tested). Each file's size and CRC are checked while it is unpacked, and a file that grows beyond the size the archive states stops the unpacking (a zip bomb); encryption, zip64 and other compression methods are refused, as are more than 200,000 entries or 20 GB. It reads archives made by the system `zip` too (tested where it exists).

**Known nit.** The strings have no plural forms, as elsewhere in the app, so "1 Dateien" and "1 Wörter" read badly.

**Telling the writer.** Both decisions above are said when a backup is restored, not left to be found out. Before "Als Projekt öffnen …" a confirm dialog explains that the backup becomes a project of its own, that the open project stays as it is and is found again under "Zuletzt geöffnet", and that the backup is to be set up again for the restored project; "Abbrechen" changes nothing. After it, a notice (kept for 15 seconds, since it is long) names the folder it was restored to and repeats the two points, and says where to set up a backup. On the welcome screen, where no project is open, only the folder and the hint about the backup are said.

## 2026-10-12: Performance and memory audit

The goal: a robust, clean and efficient editor, with RAM as a concern. A benchmark on a generated 95,000-word project (`tests/perf`, `docs/PERFORMANCE.md`) found the editor, the project handling and the backups already fast, and the memory dominated by Electron itself (370 MB for an empty window) and by the Java process of the spelling checker. What changed:

- **Java stops when idle.** The spelling checker is stopped after three minutes without a check and started by the next one (about a second); its state stays "ready", so the renderer does not react to it (a state change would have made the renderer start it again at once). The synonyms helper stops the same way. Both run with flags that give memory back (`jvmFlags`: periodic G1 collection, tighter free ratios, 512 KB stacks, a 64 MB code cache, and `IgnoreUnrecognizedVMOptions` so an older bundled Java still starts). The heap of the checker stays at 768 MB: 512 MB was two to three times slower and 384 MB ran out of memory on long units. `WRITEMIRROR_PROOF_IDLE_MS` shortens the time in development and tests.
- **A bug the work found.** The morphology helper's start left a settled promise behind (`finally` inside the function that returns the promise ran before the promise was assigned), so after the helper died the next question went to the dead process and timed out. Fixed, with the idle-stop test covering it.
- **The snapshot is `$state.raw`.** It is replaced as a whole on every update and never changed in place, so deep reactivity only proxied 131 KB of data on each autosave.
- **Versions.** Git objects are written with the native zlib off the main thread (a loose object like any other, so git reads it), and a file that is compressed already is stored at level 0. 300 MB of images: first version 5.9 s on the main thread, now 0.6 s. Objects are renamed into place but not flushed one by one (a flush per object made 190 small files take 1.3 s).
- **Backups.** Images and stored git objects go into the zip uncompressed (`store`, with the checksum read first so the header is complete and every reader can follow it): 300 MB of images in 1.0 s instead of 11.4 s. Tested against `unzip -t` and our own reader.
- **Left alone on purpose.** Typing, scrolling and switching are at the display's limit (the measured latency is the two-frame floor). The GPU process wakes about 70 times a second while any text field is focused, which a plain `<input>` also does, so it is Chromium's; a timer-driven caret blink was tried, changed nothing and was removed. A smaller heap for the checker, virtualising the sidebar (800 sheets open in 1 s) and drawing the decorations for the visible part only were considered and not needed at the sizes measured (see the list in `docs/PERFORMANCE.md`).

## 2026-10-13: Templates are global; the export preview

**Templates belong to the application.** The model: the app comes with several templates, the writer makes their own by duplicating one in a template editor, a change applies only to that template, and an export profile just names the template. Not a property of the project, so SPEC 7.3 ("copying one into the project") is changed. A custom template is stored as a base template plus only the values changed, in the app's data folder, with the fonts added to it; templates move between machines as files. Styling is by element type (all level-2 headings), not by single paragraph: the content stays free of styling (SPEC 4). Custom fonts are wanted, with the bundled ones recommended; fonts the writer adds belong to a template. **Portability is deferred**: a project that names a template the machine lacks cannot export, and keeping a copy of the template in the project (so the export is reproducible) is marked for later, because an export is done at the end and does not have to be portable.

**Order of work**: the preview (done), then the engine refactored to a list of elements with one set of properties (font, size, weight, colour, spacing, indent, numbering, page break) each, with golden tests; then the template editor with the app-level storage and custom fonts; then template import and export.

**The preview.** A pane beside the text (SPEC 7.6), not a tab of the right sidebar: a page needs width. The pages are PNG images made by the compiler, not a PDF shown by a viewer: a PDF viewer would be another dependency or a plugin the strict CSP does not allow, while images are served by the existing project-asset protocol like any image and cost nothing to display. Measured on the 95,000-word project (246 pages): a PDF takes 2.7 s, PNG pages 1 to 3 take 2.7 s, all 246 pages take 3.4 s, so the layout dominates and rasterising everything adds 0.7 s; the preview therefore makes every page in one run and the pane loads the images lazily (`loading="lazy"`, so only the pages near the window are decoded, about 8 MB each at 150 ppi). It refreshes 1.2 s after the project's revision changes, a refresh that is running is killed by the next one (`AbortSignal` on the child process), and an export waits for a running preview, so `_build` is never written by both. The old pages are deleted first, so a shorter document keeps none. It uses the saved profile, as an export does. Not done: an incremental compile with `typst watch` (a refresh of the large project takes about 3 s, small ones a fraction of that), a jump from the text to the page, and a preview of a chosen profile other than the saved one.

## 2026-10-13: The element-based style engine (engine 2)

Done as agreed (step 2 of the order above). `style.toml` now lists values per element type; the shared engine `templates/engine.typ` replaces each template's own `lib.typ`. The registry (`src/core/export/elements.ts`) is the single list the engine, the validation and the coming template editor read: 28 elements (page, body, list, all headings and levels 1 to 4, block quote, epigraph and its source, figure, captions, table, footnote, contents, bibliography, code, link, highlight, title page and its four lines) over one vocabulary of properties. **Inheritance is resolved in TypeScript, not in Typst**: the app writes the fully resolved style as literals into `_build/template/style.typ`, so the engine only reads values. The order is the element's own value, then its built-in default, then its parent's: a child's default beats the parent's value on purpose (an epigraph is italic even when block quotes are set upright; a heading takes its font from the body text unless set). Sizes in `em` are relative to the text around the element and do not compound, so elements that sit inside another (the epigraph source, the contents, the bibliography) have `1em` as their default instead of inheriting the parent's size.

**Values are data.** A style may come from another machine one day, so every value is matched against a strict pattern before it is written (a length is a number with `pt mm cm in em %`, a colour is `#rrggbb[aa]`, a font name is letters, digits and a few marks, the rest are enums or booleans) and anything else is reported and dropped; the style file cannot inject Typst code.

**The golden tests pin the look.** The three variants of the thesis template produce byte-identical pages before and after the refactor (checked by hashing the SVG pages of a fixed project and comparing against the old engine's output); the one fix needed was reproducing a space after the heading number that the old markup had. The date on the title page is pinned with `SOURCE_DATE_EPOCH`, or the hashes would change every day. The golden hashes depend on the compiler's version and fonts, so a Typst upgrade may move them; the harness says which pages and `GOLDEN_DUMP` keeps both versions to compare.

**Artikel and Prüfversion** are added as styles of the same engine (SPEC 7.4): they differ from the thesis only in `template.toml` defaults and `style.toml`. Only the fonts Typst embeds are used (Libertinus Serif, New Computer Modern, DejaVu Sans Mono) until fonts can be added to a template. The chapter-on-new-page option exists only in the thesis; in the other two the style says no.

## 2026-10-13: The template editor (first slice)

A dialog (not a pane): templates are chosen at the top, elements on the left, the properties of one element in the middle, the preview on the right, so the writer sees a change on the pages they are working on. The preview is the project's own, compiled with the template shown (`export:preview` takes an optional template id), so it needs an open project; editing does not. It is reached from the export dialog ("Vorlagen bearbeiten …") and the command palette. The preview pane beside the text stays for now, as the maintainer said, and may be removed once the editor's preview is enough.

**Storage.** `<userData>/templates/<id>/custom.toml` names the template and its bundled base, `style.toml` holds only the values changed. The id is a slug of the name and is also the folder name; a folder whose `custom.toml` names another id, or a base that does not exist, is ignored. Rewriting is atomic. Delete goes to the system trash. The renderer cannot write anywhere: it sends one value at a time (`templates:set`), and the main process checks it against the same patterns as a style file before writing.

**Reset means "back to the base".** A value the writer changed has a reset button; unset values are shown as "inherited". A bundled template cannot be changed, only copied (as decided). **Custom fonts** are built: the compiler ignores system fonts, so a font is copied into the template's `fonts/` folder and passed with `--font-path` (preview and export alike). Only files with a font extension, 40 MB at most, are copied, under a plain name (a file of the same name gets a number); removing one moves it to the trash. The families a property can name are listed by `typst fonts --ignore-system-fonts --font-path <dir>`, so no font-parsing dependency was added. The fonts belong to the template, not the project, so a project exported on another machine needs the template there (see "Templates are global"). The app does not check or bundle licences of fonts the writer adds; the panel says so. **Template files** are built: a `.wmtemplate` is a zip with the template's `custom.toml`, `style.toml` and `fonts/`. It reuses the backup's zip writer and checked unzip (no new dependency). The import is deliberately strict: the style is parsed and written again so only valid values survive, only files with a font extension and the size limit are taken from `fonts/`, the new template gets a free id (a number is added when taken), and `custom.toml` is written last so a failure leaves no half template. A template is stored as its base's name plus changes, so a file needs the same bundled base on the other machine; a file whose base the version lacks is refused with that reason instead of guessing. Bundled templates are not saved as files (they are in every copy of the app). Still open, as decided earlier: keeping a copy of the template inside the project so an export can be reproduced elsewhere.

## 2026-10-14: Heading alignment and decorative lines

**Alignment did not work** because the engine wrapped the heading's inline text in `align(…)` inside a block: Typst ignores that for inline content (checked in a five-line file). The heading block is now full width and sets `set align(…)` inside, so the text follows it. Headings always have an alignment now (default `left`), so the radio buttons in the editor always show one selected; the reset button takes a change back. Alignment is a group of three radio buttons with icons (left, centre, right) for every property named `align` (headings and the title page lines), not a select.

**Lines above and below a heading** are properties of all headings and of each level: a switch (`line_above`, `line_below`) and four fields each (colour, thickness, length, distance to the text). The line is as long as `length` (a length or a percentage, 100 % by default) and follows the heading's alignment, so a short centred line under a centred chapter title is possible. The space above and below the heading is counted from the outer side of the line. The fields appear when the switch is on. Inside the heading block paragraph and block spacing are zero, so the distance is exactly what is set. The golden test `artikel-ueberschriften` sets a variant of the Artikel template with alignment and lines, and the harness can now carry style overrides for a variant; the other baselines did not change.

## 2026-10-14: Letter case of headings; the editor's property groups

**Letter case** (`text_case`: normal, all caps, small caps) is a property of all headings and of each level. All caps is Typst's `upper()` on the heading text, small caps its `smallcaps()`, which needs a font with small-capital glyphs (Libertinus Serif and New Computer Modern have them; a font without falls back to the normal letters). It changes the heading in the text only: the contents list and cross-references print the heading as written, because Typst builds them from the heading's own text. The control is three radio buttons that show what they do ("Aa", "AA", small-cap "Aa"). Letter spacing, which usually goes with capitals, is not a property yet.

**The editor groups the properties** of an element in cards with a title (Schrift, Anordnung, Nummerierung und Umbruch, Weiteres; `PROP_SECTIONS` in the registry decides), and each heading line is a card of its own with its switch on top and the four fields in two columns. An element that has only one kind of property (a table, the page) shows no group title. "Inherited" is no longer written on every row: the label is quieter, with the word as a tooltip, and only a changed value carries a tag and the reset button. The golden test `artikel-versalien` pins the output of both cases.

## 2026-10-14: Heading numbering: format per level, and depth

**Properties.** `number_format` (arabic, roman capitals, roman small, letters capital, letters small) on all headings and on each level, and `number_depth` (0 to 6, 6 meaning all) on all headings only. They replace `numbering = "1.1" | "none"`; a style that still says `numbering = "none"` is read as depth 0 (and `"1.1"` as nothing), so no stored template breaks. The numbers join the levels with a point, each in its level's format (`II.3.a`); the level separator is not a property yet.

**Typst prints it, the app counts the same.** The engine gets a numbering pattern and the depth from the generated `style.typ` (`heading-numbering`), builds a numbering function from them (a level below the depth gives `none`, and the engine leaves out the gap after the number), and the output for the existing templates is byte-identical (goldens unchanged). `core/export/numbering.ts` formats counters the way Typst does (roman numerals, letters that repeat after Z: `aa`, `bb`), and `numberTargets` takes the numbering, so the links the export writes (`Abschnitt II.3`, or `„Titel“` for an unnumbered heading) and the editor's chips agree with the PDF. The old `heading_numbering` entry of `template.toml` is gone: the style says it now.

**The editor follows the saved profile's template.** A chip must say what the PDF prints, so the renderer asks (`export:numbering`) for the numbering of the template of the saved export profile: when a project opens, after an export saves the profile, and after the template editor closes. Choosing another template in the export dialog changes the chips once it is exported (the profile is saved then), not while the dialog is open. Figures, tables and equations keep Typst's own numbers and are not affected. The golden test `artikel-nummern` pins roman chapters, letters, small roman numerals and a depth of 3.

## 2026-10-14: Fonts for every text element, letter spacing

**Strategy.** Sizes stay relative (`em`, to the text around the element) except the body size and hairlines; fonts, weights, italics and colours can be set on every element that prints text, and an element that sets none takes it from its parent (so setting the body font or "all headings" works like a theme, without separate "font roles"). A block quote, epigraph and its source, the captions, tables, footnotes, contents and bibliography now have the same text properties as the body: font, size, weight, italic, colour. Lists are not given any: their text is the body's. A table's text size defaults to `1em`, like the other elements inside a larger one, so it does not take the body's absolute size and ignore the "font size" option.

**Letter spacing** (`letter_spacing`, a length, usually in `em`) is a property of all headings, each level, and the four title page lines, and is Typst's `tracking`. It is unset by default (no change); a level that sets `0em` overrides what all headings say. It sits next to the letter case in the "Schrift" group, because spaced capitals go together. The existing goldens did not change, and `artikel-schriften` sets every new property.

**Known behaviour.** A property that a child inherits from an element the writer changed follows: an epigraph set bold gives a bold source, a table caption follows the figure caption. Set the child to override. A font without a bold or italic style makes Typst pick the nearest one, and a font without a glyph falls back to another, so a decorative font for quotes may need testing with accents.

## 2026-10-15: Columns

**What is built.** The element "Ränder und Spalten" (the page) has the number of columns (one, two or three; radio buttons) and the gap between them, and "Abbildung" has "Über alle Spalten". The columns are Typst's page columns, set for the text only: the title page, contents and lists of figures stay in one column because the engine sets the columns after the front matter. A figure that spans floats across all columns at the top or bottom of a page (`placement: auto`, `scope: "parent"`); a table in a figure does too. The existing goldens did not change; `artikel-spalten` pins two columns with a spanning figure.

**Limits, on purpose.** Typst cannot break a flow into one column and several again in the middle of a page, so a heading cannot span the columns (only floating figures can), and a line between the columns is not offered: it would have to be drawn on every page with the margins of both sides, and the result in a thesis template is rarely wanted. Footnotes sit at the foot of the page in their column. Quote widths in percent are of the column. Not decided: whether the Artikel template should be set in two columns by default (it is not).

## 2026-10-15: Heading number details and the contents

**Heading numbers**: prefix and suffix are drawn with the heading only (not in the contents or in cross-references, which name the section "Abschnitt 1"), the separator is part of the numbering the app counts, so the chips and the links follow it. A text property (the prefix, the title of the contents) is a new property type: letters, digits, spaces and a few marks, 40 characters at most, kept as typed with its spaces, written as a string and never as markup.

**Contents.** In Typst 0.13 the dots are an option of the entry (`outline.entry(fill:)`), not of the outline; the default is written out so the unchanged look stays byte-identical.

## 2026-10-15: Tables and block quotes

**Tables.** Rules, header and stripes need to know the table (does it have a header, how many rows): the engine makes such a table again with that known, labelled so the rule does not run a second time. Only tables that ask for such a style are rebuilt; the default style still goes through Typst's own table, and the goldens did not change. A set rule inside a show rule does not reach the element and `show table.header` does not fire in Typst 0.13, so those did not work; `table.cell.where(y: 0)` would also hit the first row of a table that has no header, which is why the bold header is only applied when the table has one. Stripes start with the second row after the header.

**Quotes** with a bar, a background or padding are drawn as a box inside the indent; without them the old layout is used unchanged.

## 2026-10-15: Headers and footers

**Headers and footers.** Three elements: "Kopfzeile", "Fußzeile" (three places each) and "Seitenzahl" (look and format of the number). A place holds the page number, the last chapter heading that starts on or before the page, the section heading of that chapter, the title of the work or the author. The page numbering is read from the page itself (`here().page-numbering()`), so the title page has none and the front matter prints in its own format with no further code. "Mirror" swaps left and right on even pages: the right place is the outside edge, as the inside and outside margins already are. A header can be left off pages where a level-1 heading starts (off by default: in a template where every chapter starts on a new page, that would leave out almost every header, and the header would seem not to work). The footer with the page number in the middle is what Typst printed before, and the output is byte-identical (checked by the goldens), so the new elements cost the existing templates nothing. Headers show the chapter's title as written, with its number when the chapter has one; the letter case option applies to the whole place. Not built: different content on the first page of a chapter, running heads in the front matter, a total page count ("3 of 12", which would count the front matter too).

## 2026-10-16: Options of a template

A template of the writer's own stores changes to the base's options in `custom.toml` (`[options.<id>]` with `default` and `hidden`), next to the name and the base, so a later improvement of the base (a new option, a new value) still reaches it. The effective options are the base's with those changes applied: a default that the option does not take (a value an enum does not have, a text with a line break) is dropped, an option that does not exist is ignored, and a template file coming in is cleaned the same way. A hidden option is not offered in the export dialog and keeps its default whatever an older profile says (`resolveOptions` ignores the profile for it), so hiding "Titelseite" with the default off cannot be undone by a saved profile. Renaming options, restricting an enum's values and adding options are not offered: an option is code in the engine, and only the base can add one.

**Switching templates in the export dialog.** The profile holds a value for every option (they are saved resolved), so a new template's defaults never showed. Now the choice of another template keeps the values the writer changed from the old template's defaults, where the new template has the option, and drops the rest, which then take the new template's defaults.

## 2026-10-16: Breaking before a heading

`page_break_before` (yes or no) became `break_before` (none, a new page, the next right-hand page); a style that still says `page_break_before` is read as the new property, so stored templates keep working. The right-hand page is Typst's `pagebreak(to: "odd")`, which inserts a blank page when the chapter would start on a left-hand one. That page carries the header and footer of the template (a page number on an empty page), as Typst makes it; leaving them off is not offered. The "Kapitel auf neuer Seite" option of the thesis template still wins over a chapter break.

## 2026-10-16: The bibliography

The indent from the second line and the space between entries are `par` settings given to the bibliography element only when the template sets them, because a citation style (APA, for one) lays its entries out with its own indent and a setting that is always there would overrule it. The title is written into the generated `#bibliography(…)` call from the style (the engine cannot reach an argument of a call that the app writes), and stays a heading like the chapters, so it takes the template's heading style and the break before it. Which works are listed and in which order stays with the citation style.

## 2026-10-16: Captions and the words of references

**Captions.** Position, mark and alignment are Typst's own `figure.caption` settings, set per kind (`figure.where(kind: image)` and `kind: table`), so a table caption can be above while a figure caption is below; the defaults are the old look (below, a colon). An alignment is applied to the caption only when the template sets one.

**The words** ("Abbildung", "Tabelle", "Gleichung", "Abschnitt") are the `supplement` of figures, tables and equations (`auto`, the language's own, where the template sets none), so the native references `@fig-…` and the captions agree without code of ours; the app's own links to headings take theirs from the same style. **The editor follows the template** for what it shows: the cross-reference chips, the labels of figures and tables, and the mark after their numbers. That is the same channel as the heading numbering (`export:numbering`, now with the supplements and the caption mark in the answer), read when a project opens, after an export and when the template editor closes.

**Not done, and why.** Chapter-based numbers (Abbildung 2.1, Gleichung (2.1)): the editor numbers figures, tables and formulas across the project by counting the sheets before the open one, so every widget and the targets would need a counter that restarts at each chapter, in the sheets and in the continuous view. That is its own task; offering the setting without it would make the editor say "Abbildung 3" where the PDF says "Abbildung 1.3".

## 2026-10-16: Lists, footnote spacing, equations, code blocks

All of these are Typst settings (`set list(marker:, body-indent:, spacing:)`, `set enum(numbering:)`, `footnote.entry(gap:, indent:)`, `math.equation(number-align:)`) whose defaults the engine writes out, so the existing look is unchanged (the goldens did not move). The bullet "standard" is Typst's own per-level markers; a chosen marker is used on every level. A numbered list's format is one pattern for all levels. Whether an equation is numbered at all is not offered: the editor numbers block formulas, and a reference (`@eq-…`) to an unnumbered one is an error in Typst. A code block with a background or padding is a `block` around the raw block, left as it was when neither is set. Not offered: the number format of footnotes (the editor's markers, cards and notes panel draw the numbers it counts, so a "i, ii, iii" in the PDF would show as "1, 2, 3" in the text) and the spacing around block formulas. The golden test `artikel-listen` adds a sheet of its own to the fixture (`extraSheets` in the harness) so the existing baselines stay as they are.

## 2026-10-16: A palette of colours

Two named colours (`accent`, `accent_secondary`, in the element "Farben") that any colour property may name instead of a hex value. The name is resolved in the style once everything else is: the engine and the compiler only ever see hex (`resolveStyle` maps names to the palette's values unless asked to keep them), so nothing in Typst changes and a name cannot reach the compiler as text. The editor asks for the names to be kept, shows the name in the field and the palette's colour in the swatch, and offers a menu per colour ("Eigene Farbe", the two names); going back to an own colour keeps the colour the name had. The palette's own two colours cannot be names (a name would point at itself) and the check refuses them everywhere a value is checked. No bundled template uses the palette, so none changed; the defaults (a blue and a grey) only matter to a template that names them. More than two colours was not offered: it would be a second palette to keep in step with the text colours, and two cover an accent and a quieter one.

## 2026-10-16: Three ways to show and write footnotes

Two settings (the display, "in the margin" or "in the text", and a separate switch for the list below the text) became one with three exclusive choices: margin notes, a footnote list, floating cards. The old mode that expanded a note's text in the flow, dimmed, is gone; a stored "in the text" is read as margin notes, and a list that was switched on is the mode "list". The marker is the same widget in every mode.

**Written in place.** The small editor that used to open only as a floating popover is now mountable in any host (`mountNoteEditor`): it takes the place of the text in a margin card, or in the open row of the list, or fills the floating card. One registry per view passes document changes to the mounted editors, so undo and redo work from any of them, and the editor reaches the margin plugin (an editor-layer file) through a hook in the footnote configuration, so the layers keep their direction. The store tells the list which note is open; leaving the editor (a click elsewhere) closes the note, as before. Only the open note has an editor, so a sheet with hundreds of notes does not hold hundreds of editors.

**The narrow-window fallback stays**: in margin mode a window with no room for the column shows the list, which is a better place for the notes than nowhere. It is not a choice of its own.

## 2026-10-16: One dialog for export and templates

The export dialog and the template editor became one dialog (from the project menu and the command palette). On the left a narrow column of templates, each shown by a small picture; then the elements of the chosen template, its properties, and the preview pages. The chosen template **is** the export's template: there is no second choice to keep in step. The export's own settings (the template's options, citation style, marks, comments, warnings, the last result) are a panel at the top of the element list, called "Export"; the template's own options (their defaults and whether they are offered) stay a panel of the template, called "Optionen" under "Im Export". The profile is written when the dialog closes or an export is made, not on every click (`export.saveProfile`), and the pane beside the text and the numbering chips follow it then.

**The pictures** are made by the main process (`export.thumbnail`): a sample sheet (a chapter, a section with a footnote, a list; `src/core/export/sample.ts`) is built with the template's own files and default options in a temporary folder outside every project, compiled to PNG at 72 dpi, and the last page is kept (a title page and contents, where a template has them, come before the text). They are cached in memory by a hash of the template's files, options, fonts and the language, so only a changed template is compiled again; one at a time, so they do not compete with the preview. They need the compiler: without it the cards show the name only.

**The preview** now takes the profile being edited (`export:preview { profile }`), so a changed option or citation style shows at once.

The two stores (`exporting`, `templateEditor`) are one (`exporting`), which also removed an import cycle waiting to happen. `TemplateEditor.svelte` is `PropertiesPanel.svelte`.

## 2026-10-16: A shorter list of elements

The editor's list had an entry for every element of the style (28). Parts that are only read together now sit inside the entry they belong to, as a section below its own properties: the source of an epigraph under "Epigraph", the caption of a figure under "Abbildung", the caption of a table under "Tabelle", and the title, subtitle, author and date under one "Titelseite". The title page is an entry of the group "Seite", so the group of its own is gone. The style itself is unchanged: they are still elements (`SUB_ELEMENTS` in `src/core/export/elements.ts` says what is shown where), so stored templates and the golden tests are untouched. The dot that marks an entry with changes also shows for changes in its sections. The field ids in the editor now carry the element (`prop-<element>-<property>`), because a panel can show several elements with the same property.

## 2026-10-16: Groups that open and close, and a style for quotes in the text

The list of elements is a flat list of groups that fold out on the same level (not a tree: no step to the right, the fold mark is at the right), so the four heading levels are no longer entries of the top list. Every group starts closed; choosing an element opens its group; a closed group shows a dot when something in it was changed; a group with one entry is shown as that entry. Only one group is open at a time (opening one closes the other; a click on the open one closes it); the entries of the open group stand on a background of their own, so they are seen to belong to it; every group has a Tabler symbol (page: layout, title page: file, text: typography, headings: heading, lists: list, quotes: quote, references: link, tables: table, figures: image, equations: formula), which a group with one entry shows too. The groups: Seite (margins and columns, header, footer, page number), Titelseite, Text (body text, code, colours, highlight), Überschriften (all, levels 1 to 4), Listen (bullets and numbers, contents), Zitate (in the text, block, epigraph), Verweise (cross-references, footnotes, bibliography, links), Tabellen, Abbildungen, Formeln. The contents and the bibliography were not named by the writer: contents is with the lists, the bibliography with the references; the colours of the palette with the text.

**A quote in the text** had no style of its own (only block quotes and epigraphs did), so "Quotes: in the text, block quote, epigraph" was missing its first part. It is a new element, `quote_inline`: font, size, weight, italic and colour. It has no parent on purpose: what it leaves unset is the text around it, because such a quote can stand in a footnote or a heading, and a body size inherited from the body text would be wrong there. All templates leave it unset, so the pages of every existing golden test are unchanged; one new golden (`artikel-zitat-im-text`) pins a set one. It applies to every quote that is not a block, including the one that puts marks around a block quote.

## 2026-10-16: The size of the text and the paper size are the template's; no reset, no "changed" marks

**The size of the text did not change** when the writer set it in "Fließtext": the three templates also had an export option "Schriftgröße" (10, 11, 12 pt) which the engine applied over the body's size, so the value of the template was never used. The options "Schriftgröße" and "Papierformat" are gone from the templates; the body's size is the size (`style.body.size`), and the paper size is a new property of the page element (`paper`: A3, A4, A5, B5, US Letter, US Legal; in the section "Format" of "Ränder und Spalten"). Typst's `iso-b5` is the engine's name for B5. The golden tests are unchanged (the `abschlussarbeit-weit` variant sets the 12 pt in the style now and has the same pages); two new ones pin A5 with 9 pt and B5. **Consequences:** a project profile that has `paper` or `font_size` in `[export.options]` keeps them in the file, but they are ignored (unknown options always were), so such a project exports in A4 and the template's size until the template says otherwise. The same goes for a writer's template that gave one of these options another default.

## 2026-10-16: Styles for links and cross-references; a compact colour row

**Links** (`link`) have colour, weight, italics, a background and underlining. **Cross-references** (`references`, "Querverweise") have the same, besides the words they use ("Abbildung", "Abschnitt", …). ## 2026-10-17: Footnotes in the margin (Tufte style)

**Possible, with a package.** Typst has no margin notes of its own. The package `marginalia` (Typst Universe, by nleanba, Unlicense, i.e. public domain; Typst 0.12 or newer) places a note beside the text in the outer margin, keeps notes from overlapping (it moves one down), and swaps the side on even pages (`book: true`, which matches the page's inside and outside margins). **It is vendored** (`templates/marginalia.typ`, one file of 44 KB, unchanged, with its licence in `templates/marginalia.UNLICENSE` and a note at the top): an export must not need the network, and `@preview` packages are downloaded on first use. `loadTemplates` gives the file to every template next to the engine, which imports it. The one new dependency, justified: a margin note placed by hand (`place` and a counter) cannot avoid collisions.

**The setting** is a property of the element "Fußnote": `placement` (at the foot of the page, the default, or in the margin), `margin_width` (the notes' column, 4.5 cm) and `margin_gap` (its distance to the text, 0.7 cm). In the margin, the footnote element is replaced by `marginalia.note` (a superscript number in the text and in the margin, the footnote's own text style, the old rule and entries gone), the page's outside margin is the distance from the page edge to the notes' column, and `note_gap` is the minimum distance between two notes (12 pt if unset). The text column is as wide as the page less inside margin, outside margin, column and distance: with the defaults on A4 about 10 cm, which is Tufte's narrow text. The text of the other pages is not changed: all golden pages stay as they were, and three new ones pin the margin notes (article, thesis with a wider column, and the fallback with two columns).

**Limits.** Not with several columns of text (the text then has no edge to put notes beside): the footnotes stay at the foot of the page. Notes in a table cell, a figure or a heading are not looked at; marginalia places them where the text is, which may not be where one wants them. A note much longer than the page is not split between pages. The editor's own display of notes in the margin is the writer's choice and does not follow this setting.

## 2026-10-17: Facing pages or single pages

A property of the page element (`facing`, in the section "Format" of "Ränder und Spalten", beside the paper size): "Doppelseiten (Buchsatz)" (the default, which is what every template did) or "Einzelseiten". It is the template's, like the paper size, so a copy of a template is the way to have both. **Facing pages:** the inside margin is the one at the spine (left on a right-hand page, right on a left-hand one), a chapter may start on the next right-hand page with a blank page before it, a header or footer may be mirrored, and margin notes change sides, as before. **Single pages:** every page has the same margins (the "inside" margin is the left one, the "outside" the right one; the two fields say so), a chapter that is set to start on a right-hand page just starts on a new page (no blank pages), headers and footers are not mirrored, and margin notes stay on the right. The property decides in the engine only; the stored `mirror` settings are kept and apply again when the layout is facing pages. Pages of the existing templates are unchanged; three new golden tests (single and facing with the same settings, which differ from page 2 on, and margin notes on single pages).

## 2026-10-18: Quotation marks go only with the last of the quoted words

Backspace or Delete next to a quotation mark used to take the whole quote off (keeping its words), and Backspace at the start of a block quote did the same, its source first. The maintainer found that too easy to do by accident. Now the marks of a quote, drawn in the text or a block quote's hidden wrapper, are never deleted by a press next to them (`quoteKey` in `editor/atomicKeys.ts`):

- Outside, next to a mark: the mark is passed over and the letter behind it is deleted (Backspace after the closing mark deletes the last letter inside, Delete before the opening mark the first).
- Inside, at the edge, towards a mark: the caret leaves the quote and nothing is deleted (a block quote is left to the line before or after it).
- In an empty quote: the next Backspace or Delete takes it away; a block quote's source goes first, as before, then the quote.

The quote tool still takes a quote off on purpose, and so do the paragraph styles. Subscript, superscript, small caps and links keep their behaviour (Backspace next to the hidden wrapper takes the format off; the words stay either way). SPEC 4.2 says so.

## 2026-10-18: Feeling like a Mac app, not a web page (changes SPEC 8 for the UI font)

The aim: an app that feels native on the Mac rather than like Electron. Five points were chosen.

1. **The arrow cursor.** Buttons, rows, tabs, chips and swatches keep the arrow, as in native apps; the hand is only on what is a link (the places in the export panel and the preview's errors).
2. **No selectable chrome.** The interface is not selectable text and its pictures cannot be dragged out (`user-select: none` on the body); the writing, every field, and messages worth copying (the export's and the preview's errors, a version's text) are (`.selectable`).
3. **The system font for the interface** (approved change of SPEC 8): San Francisco on macOS, Segoe UI on Windows, the bundled Inter where there is none. The writing surface keeps the face chosen in the settings. Sizes stay (14 px, 13 px compact).
4. **Fewer hover grounds.** Rows of source lists and lists do not light up under the pointer any more, as in Finder, Mail or Notes: the group tree, the sheet cards and headings, the outline, the Literatur and Prüfung lists, the notes list, the versions, the template column and the export dialog's elements. Selection and pressed states stay, and so do the hovers of toolbar buttons (as in macOS's own toolbars), menus, buttons and chips.
5. **The window.** It opens where it was, at its size, maximized if it was (kept in `settings.json` a moment after each move or resize and on close; a place on a screen that is gone falls back to the default, `main/windowState.ts`, tested). Before the page paints it has the colour of the theme chosen last, and the window's own parts (traffic lights, native menus) follow the app's light or dark theme (`app.setAppearance` sets `nativeTheme`). The system's translucent sidebar material was tried and taken out again (the maintainer did not like it); the sidebar is instead a lighter, opaque tint of its own (`--sidebar-bg`: in the light theme halfway between the old grey-beige and the white of the text, likewise in sepia, and a little nearer the text in the dark theme).

**Subscript has no shortcut for now.** Cmd+, was both the settings and subscript; with the caret in the text it did both. The maintainer chose to leave subscript without a shortcut for now (toolbar, context menu, Format menu and palette still have it).

## 2026-10-19: The writer can assign shortcuts to the app's commands

A new page "Tastenkürzel" in the settings window (SPEC 3.8) lists every command by kind and lets the writer set, change or remove its shortcut.

- **One list of commands, defaults in the commands.** The shortcuts written in `lib/commands.ts` and `features/editor/editorCommands.ts` are the defaults. `allCommands()` and `editorCommands` return the shortcut as it is now: the writer's choice over the default (`lib/keybindings.svelte.ts`, stored as `keybindings` in the renderer's browser storage like the other app settings; only differences from the default are kept, `null` is "taken off"). **What had to change.** Typst 0.15 writes leaner SVG: fewer nested groups, glyphs placed with `matrix(…)`, and paths with relative commands (`M 0 0v 1h 1v -1Z`). The formula preview reads the baseline of an inline formula from a small marker drawn in front of it, and only understood absolute lines; it would have placed every inline formula 1pt too high. It now reads both forms (`src/core/typst/math.ts`), and sizes and baselines come out the same as with 0.13.1. The golden test that checks the margin notes leave the contents their full width measured "where the text reaches" from the nested groups; it now takes the end of each line and the median over the lines. The Vancouver citation style is called `nlm-citation-sequence` in Typst 0.15 (the old name still works with a warning); the id stored in `project.toml` stays `vancouver`.

**What the export looks like.** All 33 golden variants were set with both versions and compared as pictures. Every variant has the same number of pages, compiles without a warning, and nothing moved to another page. The differences are Typst's own changes: justified lines are spaced a little differently (a fix for text running into the margin), superscript numbers use the font's own superscript glyphs and are a little narrower, a nested list leaves about 4pt more space before what follows, footnote entries move by about half a point, and New Computer Modern 8.1 has slightly changed outlines. The golden hashes are written anew (also because the SVG itself differs). Unchanged: the short diagnostics the export maps to sheets and lines, `typst fonts`, the PNG pages of the preview, and the page count read from the PDF. Typst's own German title of a bibliography is now "Bibliografie", but the app always writes its own ("Literaturverzeichnis").

**Still the same in 0.15.1**, so the clean copy of the bibliography stays: an unknown key and a duplicate key still stop the whole document, and an `@incollection` still prints the book's title twice in APA.

To develop, install the new version (`brew upgrade typst`); the 0.13.1 that Homebrew had installed fails the golden tests now.

## 2026-10-19: Margin notes no longer also print at the foot of the page (fix)

- With the footnotes in the margin, each note was printed twice: beside the text and, as before, at the foot of the page (without the rule). ## 2026-10-19: Citations no longer stop the typesetting

The maintainer found that the document would not be set when citations were used. Investigated with real projects and the bundled Typst 0.13.1:

- **One unknown key stopped the whole document**: a citation of a work that is not in the bibliography (a typo, a work not yet in Zotero) made the compiler fail ("label `<fehlt2000>` does not exist"), in the preview and the export. Now the export's copy of the sheet prints it as its key in brackets with a question mark, in red ("[fehlt2000?]"), and the export dialog keeps listing it. A key that is a label of the export (a cross-reference) is not touched. Citations in footnotes and captions are found too (they were missed by the list of unknown citations before).
- **One flaw anywhere in the `.bib` file stopped the whole document**: Typst refuses the file for an entry that is not closed, a key used twice, or a date it cannot read ("circa 1900", a month 13), while the editor reads around them. The compiler now gets a clean copy (`src/core/bib/forTypst.ts`, written to `_build/bibliography.bib`): only the cited works and what they cross-reference, with the `@string` macros; each key once; unclosed entries left out; years and dates made readable or left out. The writer's file is never changed. An internal bibliography goes through the same copy as an external one.
- **Chapters and conference papers were printed wrongly** in the list of works: Typst 0.13 doubles the book's title of an `@incollection` ("Handbuch: Handbuch") and gives an `@inproceedings` the date of a talk ("(2020, )") in APA. In the copy both are `@inbook`, which every bundled style prints as intended ("In P. Klein (Hrsg.), _Handbuch_ (S. 1–10). Springer.").

## 2026-10-20: Quotation marks can be deleted, the current quote shows, Enter leaves a block quote (changes SPEC 4)

The maintainer found the quote tool hard to use: the marks read as characters, but a press next to them never took them (Backspace after the closing mark deleted the last letter inside), and there was no way out at the end of a block quote, whose caret is kept inside its hidden wrapper.

- **Two presses take a quote off.** This replaces "marks go only with the last of the quote's words" (2026-10-07). Backspace or Delete next to a mark, from outside or inside, marks the quote (`armedQuoteField` in `quoteState.ts`): it is drawn on the selection's ground, marks and all, and nothing changes. The next press takes the quote off and keeps its text (`removeQuote` in `core/typst/quotes.ts`); a block quote's source moves behind the text, so nothing is lost, and an epigraph loses its label. Any other edit or move of the caret lets the mark go. This is the select-first step that images, formulas and footnotes have, without selecting the quote's text, which a second press would delete. An empty quote still goes with the first press, a block quote's source first.
- **The quote the caret is in shows.** Its two marks (of the innermost quote) are in the accent, so it shows where the quote begins and ends and that the marks are a pair; a block quote has its rule in the accent instead (with or without marks).
- **Enter leaves a block quote as it leaves a list.** Enter at the end of the text starts a paragraph inside the quote; Enter on that empty last line moves it out, behind the quote (and behind an epigraph's label), where the caret starts a paragraph (`leaveBlockQuote`). A quote with nothing else in it goes. This also gives a way out of a block quote at the end of a sheet.

Not done (offered, not chosen): typing the closing mark at the end of a quote to step out of it, and a tooltip on the marks.

## 2026-10-20: Block quotes have the ground of quotes in the text

A block quote is drawn on the same faint ground as a quote in the text (`--color-quote`), beside its rule, so the two read as one element. The ground covers the quote's lines and the space between its paragraphs, not the gap above it. A quote in the text inside a block quote lies on both grounds and looks a step deeper, like a quote inside a quote. An epigraph keeps its look (no ground, no rule).

## 2026-10-20: Citations in the sentence are underlined text, not pills

The maintainer found the chips of the five forms too alike, the prose form above all, and suggested a strong underline for it. A citation in the prose or the author form ("Smith (2020) zeigt", "bei Smith") is part of the sentence, so it is now drawn as text: the text's own size, weight and colour, with a solid 2 px underline in the accent (`.cm-cite.prose`, set when every work of the group has one of the two forms, `inSentence`). The citations in brackets, the normal and the year form, keep the pill; `form: none` keeps the dashed outline. The states keep their signs: the mark's ground to check later, a dashed underline in the danger colour for a work that is not in the bibliography, and the accent ring while open or selected. A cross-reference stays accent text with a dotted underline, so the two underlined kinds differ in colour and line. The author form was added to the maintainer's suggestion because it is part of the sentence in the same way; it is one condition in `groupChipFor` to take it back.

**Same size as the text.** The pills were set smaller than the text (0.88 em), the underlined citations at its size. Every citation is now at the size of the text around it (`.cm-cite` at 1 em), and so are the words beside the chips in the source of a block quote ("vgl."), which were 0.82 em. The marker of a place without a citation ("Beleg fehlt") is at the text's size too, and the pills are all as tall: the dashed line of a work not in the bibliography or not printed is an outline just inside the edge (`outline-offset: -1px`), not a border, which made those pills 2 px larger. The free-text source of an epigraph, a line of its own under the motto, stays smaller.

**Quieter pills.** At the size of the text the pills stood out too much. They now have the weight of the text around it (was 500) and a paler ground, the accent at about half the selection's strength (`--selection-strength * 0.55`, in every theme); a hover gives the selection's full ground. The accent text stays, as the sign of a citation that can be opened. Compared in the app with three other variants (weight only; a still paler ground with the text in the text's colour), chosen as the calmest that still reads as a citation.

## Proofreading long sheets (2026-10-24)

**What went wrong.** The sheet is sent to LanguageTool as units (paragraphs, headings, list items, notes), 60 at a time, and the marks were drawn only when all of them were back. Measured with the real server (4 requests at a time): about 600 words a second, so 30,000 words took 47 s, and a paragraph of 30,000 words as one unit took 24 s, over the 20 s limit of a request. A request that timed out made the whole call fail, the editor then waited for a state change that never came, and "being checked" stayed on for good.

**What is done.** (1) A paragraph longer than 1,500 characters is cut into units at the ends of sentences (at a space when one sentence is that long), never inside markup or a stand-in (`splitLong` in `src/core/proof/extract.ts`). (2) A unit the checker does not answer comes back as `null` and the others stand; only a server that does not answer at all marks the checker as failed. Such a unit is left alone until the next full recheck. (3) Units go in groups of 16, those nearest to the middle of what the writer sees first, and the marks found so far are drawn after every group, and at the start from what was remembered, so a long sheet fills in near the caret within seconds. (4) When the text changes during a check, the rest of the old pass is dropped at once (what was found is kept) and the text is read again. Not done: a check that uses more of the machine (the server's own threads), or a check by the paragraph that changed only on a sheet's first opening.

A folder that is left out of the export is no longer a flag but a place. **The material** is a section under "Alle Abschnitte", headed "Material", whose folders stand side by side at its top level (any number, with folders in them as in the document); the heading is not a folder and cannot be chosen. In the tree of the project the material is a group named `:material` (`MATERIAL`; a colon cannot be in a name a writer gives) whose children are those folders, so every path, the order lists in `project.toml` (`":material"` is the order of its folders), the settings of an item, moving, renaming and the caches work as they do in the document (`projectFile` says which file a path is). The group counts for nothing in the document's totals, is never in the export, and everything in it is `inExport = false`; its sheets have a status like any other (they are not scratchpads). It holds folders only: a sheet cannot be made or moved at its top level.

**Moving.** "In das Material verschieben" in the menu of a folder, a drop on the heading or on a folder of the material, and "Neuer Ordner im Material" (in the menu of the "Alle Abschnitte" row and of the heading) put things there; "In den Export aufnehmen" in the menu of a folder of the material, or a drop on "Alle Abschnitte" or any folder of the document, take them back, with their sheets and settings (status, goal, icon). **Migration.** A folder that is marked `export = false` in a project (the old way) is moved into `material/` when the project is opened, with a number added to a name the material has, and loses the mark; the mark stays for single sheets, which are scratchpads. The earlier entry (the folders of the flag standing outside) is replaced by this one for folders; the one about scratchpad sheets stands. The history of versions keeps the files of `material/` like any other.

**The versions and the material (2026-10-25).** The version store always kept the files of `material/` (it keeps everything of the project that is not hidden, `_build/` or too large), but its list knew only the sheets of `content/`: those of the material were shown as plain file paths. `sheetOfPath` now names a sheet of `material/` by its place in the tree (`:material/…`), so the dialog lists it with its first line, with "Material ·" in front of it, and "Abschnitt wiederherstellen" brings it back (the folder with it, if it was deleted); the comparison of whole versions and "restore all" worked on files already.

**No button for the material (2026-10-25).** The link under the tree and the "+" on the heading are gone. The place for a first folder is made while one is dragged: when a folder is picked up and there is no material yet, a dashed "Ordner hier ablegen, um ihn aus dem Export zu nehmen" appears under the tree (and goes when the drag ends); dropped on it, the folder is the first of the material. Once the material exists its heading is the place to drop on. An empty folder in the material is made from the context menu of the "Alle Abschnitte" row or from that of the heading (the "+" of the groups column makes an ordinary group, as before).

## 2026-10-25: Third-party notices, and an Info tab in the settings

Everything Ezetta ships that is not its own code is named with its license in `THIRD-PARTY-NOTICES.txt` (root of the repository, and in the package's resources next to `LICENSE`). It has three parts: the programs and data that travel with the app (Typst, LanguageTool, the Java runtime, OpenThesaurus, WordNet, Marginalia, Electron), described by hand with their license, source link and where their own license texts are in the package; the libraries and fonts built into the app's code, with their license texts; and the Apache License 2.0 in full, which Typst requires.

**Generated, and checked.** `scripts/notices.mjs` reads the app's source for imports, follows each package's dependencies in `node_modules`, and writes the license text of every package (identical texts are shared). `npm run notices` rewrites the file; `npm run check:notices`, part of `npm run check`, fails when the committed file differs, so adding or updating a dependency cannot go unnoticed. The list errs on the side of too many packages (a library's whole dependency tree, build-time parts of the Svelte package included), never too few. Packages without a license file of their own are listed with the license their `package.json` names and their author.

**Shown in the app.** The settings have a fourth tab, "Info": the name, the version, one sentence on the license, and the notices in a scrollable text. The settings window reaches every platform (Linux has no menu bar), and on macOS the app menu's "About Ezetta" opens the same tab instead of the system's plain panel. The text comes from the main process (`app.about`), which reads the file from the package's resources, or from the checkout in development.

**Not done.** A name and a link for the project's own source code and the copyright holder are not in the file yet; they follow with the public repository. The licenses of the Rust libraries inside the Typst binary are not reproduced, only referred to at Typst's repository.
